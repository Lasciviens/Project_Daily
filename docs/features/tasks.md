# Tasks

> Moved out of CLAUDE.md on 13.10.2026 (word for word, apart from translated quotes). This file describes how the feature works and why. The rules Claude must follow while changing it are in `.claude/rules/tasks.md`, which Claude Code loads by itself when a matching file is read or edited.

## One table for every domain

**Tasks — one table for every domain.** `tasks` is the single source of truth for tasks across every page; **never create a per-feature task table.** Enums: `domain` `personal|work|media` · `section` `inbox|today|tomorrow|this_week|backlog` · `status` `open|in_progress|waiting|done|cancelled` · `priority` `low|medium|high` · **`source_type` `manual|movie|tv_series|media|calendar|ai|training_session|project_item`** (widened by migrations 039 and 047). Canonical queries: Work board `domain='work' AND status != 'cancelled'` · a day's list = `fetchTasksForDay` + `taskRules.onDay` (One task model below) · media plans `domain='media' AND source_type='media'` · inbox `section='inbox' AND status='open'`.

## completed_at is the "when was it closed" clock

**`tasks.completed_at` is THE "when was it closed" clock (migration `129`).** A BEFORE trigger (`trg_tasks_closed_at`) stamps it whenever a task moves into done or cancelled (a Google pull may send Google's own time) and clears it on reopen — every writer is covered. Never read `updated_at` for "finished": any write moves it (a Google Tasks sync every 20 min, `swapTaskOrder`, the title mirror), which is how Home said "All done for today · 1 task finished" on a day with no task. `taskRules.closedDay`/`closedOn(task, day)`: closed on THAT calendar day, read from `completed_at` only — the one "done" rule of every page (see **One task model** below; the 24-hour rule and the `updated_at` fallback are gone).

## One task model

**One task model (12.10.2026, owner: "the same thing reads differently on every page").** Daily, Home and Work used to count "open", "done today" and "next" and run task actions each their own way. Now:
- **Rules** — `todo/taskRules.ts` (pure, `verify-task-model`, with a guard against hand-written open/done checks): open = open, in progress or **waiting**; done/cancelled **on a day = closed that day** (`completed_at`, migration 129); `onDay` (due that day; closed that day; on today also every open overdue task **whatever its section** — one filed in the Inbox or Backlog used to vanish from Daily and Home while Tasks and Work called it overdue — and undated Today-section rows); `dayTasks` (open: overdue first, then sort order; done, cancelled, counts), `countTasks` (Work), `openOnDay`/`weekCounts` (week strips, week card, month dots), `taskGroups` (the Tasks tab), `isFocusedOpen`.
- **One day read** — `useDayTasks(day)` (`fetchTasksForDay(day, today)`: due that day, closed that day, and on today the open overdue + undated Today rows) is what Daily's day pane, Daily's rail, the week strip's today count, Home's tasks card, overview and brief all read (a failed read says so, never an empty day); `useTodayOverview(day)` adds the schedule.
- **One day schedule** — `daily/daySchedule.ts` (pure): `buildDaySchedule` (one-off blocks + yesterday's tails, weekly plans, unlinked Google events), `aheadOnDay` (not yet over, never a closed task's block; the first is "Next up", "Now" while under way), `plannedMinutes`. DayAgenda's header, Daily's rail and Home's hero all show these (the overview's clock ticks every minute on today). A weekly plan's occurrence is never `closed` (a session trained early still reads "next" until its day becomes a block).
- **One action hook** — `todo/hooks/useTaskActions` (`setDone`, `setStatus`, `cancel`, `reopen`, `toggleFocus`, `remove`, `open`, `edit`, `move`/`skip`): ToDoItem (Daily, Home), Work's cards, list, focus strip and drag, and the Log card's Mark done. A training task routes to the session's own actions (Skip asks why, Delete asks + Undo, they toast); every other delete asks first and offers Undo (`docs/features/delete-undo.md`), and every action says its result. Cancel works on a done task too; Focus shows only on open ones.
- **Migration `143`** clears `is_focused` whenever a task is done or cancelled, for every writer (Daily, Google pull, the assistant), and cleared the ones already closed (`verify-db-task-focus`). Reopening doesn't bring focus back.
- Ask AI's TODAY'S TASKS context reads the same day list. Not yet on the same rules: the server-side counts in `push-send`, `phone-gateway`'s `tasks_today` and `ai-proxy`'s day summary.

## start_date opens a window

**`tasks.start_date` (migration `069`) is `due_date`'s OPENING edge**, not a second deadline: `start_date=A` + `due_date=B` means "do this between A and B", and `due_date` stays the **sole** deadline representation — so overdue, the brief, the push, `phone-gateway` and `workMeta.ts` learn no new concept. `ToDoItem` renders **one** range chip *instead of* the due chip (never both — that row's own comment records a real 136px-of-393px title-starvation bug) and still takes its colour and ⚠ from `due_date`. `TasksPanel` gains an **"Open now"** group (`start_date ≤ today < due_date`), computed client-side off `fetchAllTasks`' existing `select('*')`, so before 069 `start_date` simply reads `undefined` and the group stays empty — no probe, no query. The window's last day belongs to Today (on `due_date` the deadline is what matters), and Open now only ever takes rows *from* Upcoming, so nothing renders twice. **A window predicate is NEVER added to `fetchTasksForDay`** — a `42703` there takes down `DayView`, `DayQuickRail`, `HomePage` and Home's `TodaySummary` at once. Written on **both** `UnifiedPlanModal` save paths via `TaskWindowField` (season chips reusing `windowChips`' math; it could not live in `taskExtra`, which is a `React.ReactNode` with no access to `form`/`patch`), and `tasksApi` retries the write without `start_date` on `42703`/`PGRST204` (the `recipes.fiber_g` precedent) while create omits the key entirely when unset. Fixed in the same pass: `CreateTaskInput` had no `description`, so the Notes textarea was **silently dropped on create** while edit persisted it.
