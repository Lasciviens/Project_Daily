# Books and Kobo

> Moved out of CLAUDE.md on 13.10.2026 (word for word, apart from translated quotes). This file describes how the feature works and why. The rules Claude must follow while changing it are in `.claude/rules/books.md`, which Claude Code loads by itself when a matching file is read or edited.

## Overview

`/books`, `src/features/books/`, tabs **Library · Stats · Send to Kobo · Kobo** (`?tab=`; the old `reading` opens Stats). **Library** (migration `126`, `books`): reading now, **Up next** (the queue: want-to-read ordered by `queue_order`, ↑/↓), every book as a cover grid with search (accent-folded, ø/æ/ı mapped), status pills, sort and "On the Kobo"; a likely-duplicate banner offers **Merge** (`mergeBooks` repoints events, fills empty fields, deletes the loser — a suggestion, never automatic); the `book` popup (`BookSheet`: status, dates, rating, review, notes, recent sessions, **Find cover and details** → `book-meta`). **Stats** (`StatsTab` + `components/stats/`): tiles (today vs goal, a **retroactive streak** — a day after the Kobo's last complete sync is *unknown*, never zero, `readingAggregate.dayState` — week, month, year, books finished, pages), **Currently reading** (progress, page X of Y, time, sessions, speed, about how long to finish), the **reading log** (sessions with times and pages pp. a–b), minutes per day (unknown days dashed), books in the window (news summed into one row), finished books by year, the year by month, time-of-day grid, the goal (`reading_settings`). Daily's glance board has a **Reading** cell (one of six fixed modules; every grid full). Data comes from our KOReader plugin `scripts/kobo/lascisboard.koplugin` (see **Kobo plugin** below); setup runbook `docs/kobo/SETUP.md`. Pure: `readingAggregate.ts` (`verify-reading-aggregate`), `readingSync.ts` (`verify-reading-sync`), `opdsFeed.ts` (`verify-kobo-feed`); the last two are GENERATED into `kobo-sync` by `scripts/sync-kobo-shared.mjs` (`--check`). **Send to Kobo** (migration `125`): upload EPUB/KEPUB/PDF (≤ 50 MB, ≤ 100 MB waiting since migration 127) to the private `kobo-inbox` bucket (stored as `book.<ext>` — Storage refuses brackets and non-ASCII names; the real name stays in `filename`); the plugin downloads it on the next Wi-Fi wake (fallback: the OPDS catalogue, added over SSH with `scripts/kobo/add-opds-catalog.lua`). Files are deleted 24 h after download or 7 days unfetched (feed/inbox read + daily cron). Game-media uploaders stop at **850 MB** so the project stays under the 1 GB wall. Kobo card on Settings → Subscriptions (last sync, complete-up-to, plugin version). Device work: `docs/kobo/REFERENCE.md`. **Round 2 (05.10.2026, migration `127`, plugin 1.1):** **News Downloader issues are `books.kind='news'`** (set once when the row is made, from their folder) — never in Reading now, Up next, the book grid or Daily's book in hand, but kept under their own **News (N)** chip in the Library; the book popup moves a row between book and news; their minutes still count ("News · …" in Reading → Books). **Kobo tab** (`components/kobo/`, `KOBO_BOARD`): the device (last sync, battery at last sync, KOReader/plugin version, whether it has applied the latest changes, what it refused), **Sleep screen** (mode, your own images — resized in the browser to 1072 × 1448, private `kobo-sleep` bucket, ≤ 10 MB/40; after each upload the rev is raised again so a sync mid-upload never skips the image — one picked image or random, Bookshelf options, more options folded), **KOReader settings** (457 settings in 23 groups; Reset stores `null`, so the Kobo deletes its own value; searchable, from `koboSettingsCatalogue.ts`, GENERATED by `scripts/kobo/gen-settings-catalogue.mjs` from `docs/kobo/koreader-settings.json` — every key read from KOReader v2026.07.1 with a file:line; risky keys (plugins/statistics off, SSH, proxy, DPI, language, delete-at-end…), keys this Kobo lacks hardware for, Lua-table/array values, secrets, frontlight levels and keys that could stop typing or page turns are left out; the same generator writes the plugin's allow-list `lbsettings.lua` (key → Lua type) — the Kobo writes nothing else; `a.b` keys are one field of a table setting, `pt:` keys are Project: Title's own SQLite config), **Menu order** (the Kobo reports its menus; move items up/down or to another tab; only changed lists are stored; KOReader asks to restart), **Asked on the Kobo** (AI answers). Only the owner's changes are stored (`kobo_device_config`: settings, menu_order, sleep_image_id, `rev` raised by a trigger); the plugin applies a rev once and reports (`kobo_device_state`). Pure: `koboSettings.ts` (cleanSettings, cleanMenuOrder, moveMenuItem), `koboDevice.ts` (captures, ask prompt), `kobo/settingsView.ts`, `kobo/menuView.ts` — `verify-kobo-settings`. **Statuses and ratings set in the app go to the Kobo** (`readingSync.pushFor`: Finished → complete, Reading → reading, Paused/Dropped → on hold, rating 1–10 → 1–5 stars; Want-to-read is never pushed; the plugin writes the KOReader sidecar, skips the open book, confirms through `/applied`, so the next sync reads the same value back — no flip). Nickel (Kobo's own reader) is never written. **Covers:** the plugin sends a book's own cover from inside the EPUB (≤ 400 KB, public `book-covers` bucket, ≤ 20 MB in all, app uploads included); books it can't (no cover, too big, not on the Kobo) get an online cover by themselves, 5 per visit, **cover only and only on an exact title (+ author) match** (`useAutoCoverLookup` → `book-meta` `mode: 'cover'`; the popup's button still fills every detail); the book popup can upload a cover or take a link (`cover_source`). The book popup edits every detail (series number, language, publisher, year, pages, ISBN, about — kept in the app, the Kobo's file is not changed; the description is saved only when edited) and lists the questions asked about the book. A Paused book stays Paused when the Kobo reports "on hold". | **Round 3 (05.10.2026, migration `128`, plugin 1.2):** **news never has a status** (`books.read_status` nullable; trigger `books_kind_rules` clears status, rating, queue place and read dates for `kind='news'` from every writer; the book popup hides them). **Library** browses by **All books · Want to read · Authors · Collections (series) · Categories · Subjects · News** (`?view=&group=`; pure `libraryFacets.ts`: case/accent-folded grouping with the majority spelling, series order, `suggest`/`canonical`), each tile marks **Kobo** when the file is on it; `books.categories`/`subjects` (text[]) are edited with **`SuggestInput`/`TagInput`** — typing offers the library's own spelling and a near match becomes it, so one author never lives under two names. **Send to Kobo** opens each file in the browser first (`epub/`: a tiny ZIP reader/rewriter, OPF read/write, KOReader's partial MD5 — `verify-epub-tools`, checked against Python's zipfile and node's crypto): cover, title, author, collection + number, language, categories, subjects, Want to read/Reading, missing fields flagged, an existing copy named; **Write these details into the file** (EPUB) writes ONLY the fields that changed, in place (ids, sort names, illustrators and translators kept; only `aut` creators are read as authors), so the Kobo shows them; the library row is made by the final file's md5 before upload (`sendPrepared`), so the Kobo's next sync matches it. The same file picked again starts from its library row (categories kept); a hand-added book with the same title can be the target (**Send as that book**); typed fields replace, the file's own facts only fill gaps (`updateFor`); a name one or two letters off an existing one offers **Did you mean …** (`nearMatch`, swaps count as one). The language is a code picker (hyphenation follows it). KEPUB keeps `.kepub.epub` on the Kobo (`lbcore.bookExtension`). The reader menu is captured in `onCloseDocument` while the book is still open and sent by the next sync (`pending_reader_menu`), only when fully built. **Kobo tab** = sections **Overview · Sleep screen · Settings · Menu order · Asked** (`?section=`, a sticky list from the laptop, pills on a phone): Overview has the device, a **Storage** card (`kobo/storageView.ts`: free/total from plugin 1.2, books/news/other) and **Your changes**; **Settings** groups the 452 settings into **8 areas** (`kobo/settingsAreas.ts`, chart-token colours) → sections → rows, each with a **`HelpTip` "?"** (hover with a mouse, tap on touch: plain help, an example, default, when it applies, where on the Kobo); the text comes from `docs/kobo/settings-help/*.json` (written from the KOReader source, merged by the generator, which refuses a setting without help); **Common / All settings** (`level`), search, **Changed by me**. Menu order hides separators next to hidden items and refuses to edit a report that names under 60 % of its items (`labelCoverage`; plugin 1.1's reader report was taken before KOReader built the menu). Plugin 1.2: `menuReport` builds the menu first (`setUpdateItemTable` while `tab_item_table` is nil) and the reader menu is re-reported once per version; `deviceFacts` adds `util.diskUsage('/mnt/onboard')`; library facts add the file `size` and `keywords` (sidecar `doc_props.keywords`, `PT_bookinfo_cache.sqlite3`/`bookinfo_cache.sqlite3` read-only). Verified: `verify-library-facets` (41), `verify-epub-tools` (50), `test-lbcore` (80), `verify-kobo-settings` (86), `verify-reading-sync` (82), `verify-reading-aggregate` (64). **Round 4 (06.10.2026, plugin 1.3, no migration):** every time setting is a number + unit (ms/s/min/h/days) shown as "1 h 30 min" and stored in KOReader's own unit (`kobo/durations.ts`, `DurationInput`); the sleep/switch-off/standby/auto-dim timers can be Off (-1). Lua-table settings are a catalogue type `list`: the warm-light **fixed times** (`autowarmth_scheduler_times`, decimal hours) and **warmth through the day** (`autowarmth_warmth`, +1000 = night mode) with their own editors (`ListEditors.tsx`), page margins and word spacing as two-number editors; `kobo/settingRules.ts` hides sub-settings that don't apply (fixed times only for the fixed-time modes, location only for sunrise/sunset…). Font settings are pickers (`FontPicker`, `fontChoices.ts`): KOReader's bundled fonts until plugin 1.3 reports the Kobo's own list in its report. 456 settings; `verify-kobo-settings` (180), `test-lbcore` (115). Still not editable: per-type font families, keyboard layouts, dictionaries order, style tweaks.

**Merge keeps every reading event (28.10.2026, audit).** `mergeBooks` reads both books' events page by page (they were capped at 1,000 by the server, so the loser's delete — `ON DELETE CASCADE` — took the rest, and a duplicate past the survivor's first 1,000 could stop the merge half-way on the unique key), and deletes the loser only when nothing but duplicates is left on it; otherwise it says so and Merge can run again. `scripts/verify-book-merge.cjs`.

## Kobo plugin

**Kobo plugin (`scripts/kobo/lascisboard.koplugin`, AGPL-3.0-or-later).** `main.lua` + pure `lbcore.lua` (`lua5.1 scripts/kobo/test-lbcore.lua`). On `NetworkConnected` (at most every 10 min) and when a book closes while already online it: (1) reads KOReader's `statistics.sqlite3` `page_stat_data` from a cursor (`start_time`, one day of lookback on the first batch, 2,000 rows per request) and posts it with the books it belongs to — **the statistics database itself is the outbox**: the cursor moves only after a 2xx, and the server's unique key makes any re-send harmless; (2) once every ~20 h (and on *Sync now*) sends the whole library: history sidecars (`summary.status/rating`, `percent_finished`, `partial_md5_checksum`), **Nickel's `KoboReader.sqlite` opened read-only** (`ContentType = '6'` sideloaded rows: title, author, ISBN, series, language, description), a walk of the home folder, and the statistics `book` table, all keyed by KOReader's `util.partialMD5`; (3) downloads the Send to Kobo inbox into `/mnt/onboard/Send to Kobo` (skips a file the OPDS catalogue already saved) and acks each; (4) once a day after 05:00, in the file browser only, runs the News downloader's sync (`self.ui.news_downloader`). It **never turns Wi-Fi on** and does no network work on suspend (PLAN §3.0); settings are re-read from `settings/lascisboard.lua` on every use because the file browser and the reader each hold an instance. Install/secret: `deploy-plugin.sh`, `set-plugin-secret.lua` (secret on stdin over SSH), runbook `docs/kobo/SETUP.md`. Every KOReader call was checked against the v2026.07.1 source; **not yet run on the device**. **1.1 (round 2):** `lbcontrol.lua` applies what the app sends after the last sync request, in the file browser only — statuses/ratings into sidecars (`filemanagerutil.saveSummary`, never the open book), settings into the live `G_reader_settings` (+ flush; `a.b` = a field of a table setting; `pt:` = Project: Title's `PT_bookinfo_cache.sqlite3` config, read on its next start; a hard deny list in `lbcore` refuses risky keys whatever the server sends), sleep images into `<data>/lascisboard-sleep` (exactly the app's set; `screensaver_dir`/`screensaver_document_cover` point there), `settings/<side>_menu_order.lua` (KOReader's own user override; then `askForRestart`), and reports values + menus (`/applied`, at most daily unless something changed). Lasci's Board sits first in the 🛠 tab unless the owner moved it. `lbextras.lua`: the EPUB's own cover (container.xml → OPF → image, via `ffi/archiver`, never renders the book); today's minutes / goal + streak in the bottom bar (`addAdditionalFooterContent`, computed locally from `statistics.sqlite3`, once a minute, toggle in Settings); **Capture a note…** (menu, a gesture action, or "To Lasci's Board" on a selection) → an outbox file sent with the next sync; **Ask Lasci's AI** on a selection (Explain · Translate · This word · Who is this? · a question; answers in English by default, Turkish/Norwegian in the plugin's settings; Wi-Fi asked for; at most 100 a day; the key travels in a header). Battery, charging and the KOReader version go with every sync.
