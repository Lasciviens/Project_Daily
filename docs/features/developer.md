# Developer page

> Moved out of CLAUDE.md on 13.10.2026.

## Overview

Standalone `/developer` (sidebar footer, More sheet, Settings ⚙), pill tabs synced to `?tab=`. Tabs: **Connections** (see Connections below), **Memory** (see AI), **Activity** (CRUD audit trail — `audit_logs`, written by DB triggers, migration `037`; filters by table/op/actor/days, 30-day retention swept probabilistically inside the trigger) and **Errors** (`app_error_logs`), plus a "Reindex AI search" button. Activity, Errors and Memory are list + detail (`developerBoards.ts` → `LIST_DETAIL_BOARD`): phones and tablets open a row in place (Memory: its edit sheet); from the laptop toolbar + list sit in main and the picked row opens in a sticky pane beside them (two tracks from 1920; it stops at three). `paneSelection` keeps the picked row, else the first listed row; Activity shows no pane for an empty list; Memory asks before discarding an unsaved pane edit. The pane is `ActivityLogDetail` (the diff), `ErrorLogRows`' `ErrorDetail` (message + context with copy buttons) or `MemoryDetail` (an inline editor sharing `MemoryFields` with the sheet); the picked row is `bg-accent-50` + `aria-current`. The header stops over the tab's board. Audit triggers cover user-authored tables only — bulk-synced tables (hevy_*/health_*/strava) are deliberately excluded to avoid sync-spam; `actor` distinguishes 'web' (browser session) from 'service' (AI/webhooks, service-role writes). Activity is a **timeline** (`ActivityLogRows.tsx`, tones for created/updated/deleted): a plain-language sentence per change, same-transaction cascades grouped, a readable diff on expand. Both log tabs read through `developer/hooks/useLogs.ts` and confirm "Clear all" first.

## A user-facing activity feed (not built)

- **Activity Log / stats widget** (user-facing feed, if ever built) — it must be **immutable append-only**: SELECT + INSERT policies only, and the **absence** of UPDATE/DELETE policies is the enforcement mechanism. Sketched event vocabulary: `task_created`, `task_updated`, `task_completed`, `task_cancelled`, `media_added`, `media_status_changed`, `media_planned`, `media_completed`, `media_dropped`, `ai_action_proposed`, `ai_action_confirmed`, `ai_action_cancelled`, `calendar_event_synced`. **`audit_logs` (migration 037) already covers the CRUD audit trail — don't rebuild that**; this would be a user-facing feed, not an audit table.
