# Shop

> Moved out of CLAUDE.md on 13.10.2026 (word for word, apart from translated quotes). This file describes how the feature works and why. The rules Claude must follow while changing it are in `.claude/rules/shop.md`, which Claude Code loads by itself when a matching file is read or edited.

## Overview

See Shop section below. Wishlist (general wishes + models, deals, the Prisjakt price watch) · Quick list (Kassalapp chain prices) · Owned (what you own and owned, money chains, Try other prices, Stats). Its own nav entry (sidebar, More sheet).

## Shop Feature Detail
`/#/shop` → `ShopPage` (`src/features/shop/`), rebuilt 08.10.2026 (migration `137`) into three views, `?view=` (`bought` opens Owned): **Wishlist · Quick list · Owned** (Owned has **Things | Stats**, `?tab=stats`). Phones show no counts in the view control. The header bar keeps one row and the view switch one width on every view (owner, 03.11.2026: a tab switch never reshapes the bar): on a phone Owned's Things | Stats and its "More ways to add" menu sit in the row right under the bar (they used to add a row to it and narrow the switch); from a tablet they share the bar's row. A wishlist row lives a life: **To buy** (`status 'wishlist'`) → **Mine** (`'bought'`) → **Sold or gone** (`'bought'` + `disposal` facts). - **Autofill in the add sheet** (Shop step B, owner, 10.11.2026: "full gas"; after the 20-product hit-rate test the same day). Asked once typing rests (500 ms).
  - **The facts**: one line each — a tick, what it is, its value, its source and confidence. A fact with a field of the form (name, price, picture, store, category) fills that field only when it is empty or still holds an earlier fact's value, **never over what the owner typed**; its row then says "you changed it" and nothing of it is saved; unticking empties the field it filled, ticking puts it back. The others (brand, model, EAN, condition, return days, Prisjakt no., specs) are edited in their row (tap the value: an EAN typed with spaces is kept as 13 digits, a wrong check digit unticks it; spec rows one "Name: value" a line); an edited fact's source is "you" and a new read never replaces it. A surer fact is never replaced by a less sure one (a title's *check* brand never beats a page's *exact* one).
  - **Saved**: the kept EAN in `ean`; the kept facts that are no column of their own in **`shop_items.facts`** (migration 191, below) — only 191's keys (`brand`, `model`, `ean`, `condition`, `return_days`, `prisjakt_id`, `specs`), each exactly `{value, source, confidence}`, the source one plain line of at most 200 characters, each value its key's own shape (brand 1–120 and model 1–64 plain characters, EAN 13 digits, a known condition, return days a whole number 1–400, Prisjakt's number 1–12 digits, 1–30 spec rows `{name ≤ 80, value ≤ 300}`), the whole at most 8 KiB (`shop_item_facts_ok`; `factsKept.factsToSave` writes that shape — a value not in it is left out, never sent to be refused — and cuts spec rows from the end until it fits). A form fact (name, price, picture, store, category) is its column, never a fact.
