## Overview

**Command-center layout** on PageBoard (`workBoard.ts`), flowing and scrolling in `<main>`: a sticky translucent header (date, done/active/overdue status pills — `countTasks`, done = closed today — New task, rail toggle) → `FocusStrip` (focused open tasks, horizontal snap-scroll; a closed task leaves it, migration 143) → collapsible `OverdueStrip` (overdue is a property, not a column — except in_progress tasks, which stay on the board) → `WorkToolbar` (Board/List toggle, persisted, + quick-add + search + priority filter; search and priority wrap as one group) → `WorkBoard` (4 explicit columns from `lg`, each at most 28rem, per-column scroll + DnD; stacked collapsible below `lg`) or `WorkListView` (dense triage rows, status-cycle dot, overdue-first sort; Done / Focus / Delete sit in one ⋯ menu on phones and touch screens so the title keeps the row, and are a hover-revealed button row with a mouse from `md`). `WorkSidebar` (Today/Notes/This week/Pinned links) counts its columns by its own width (1 · 2 from 36rem · 4 from 60rem): a band under the board on phones, tablets and 1280/1469 laptops, a column beside it from 1920 (the board spans 2 tracks at 1920, 3 at 2450). List view keeps the list in the 56rem main track with the rail beside it from the laptop (two tracks, 2×2, from 1920), stops at three tracks and ignores "Hide side panel" — that toggle exists only in Board view from 1920 and gives the rail's track back to the board. The command bar stops where the board does (`workHeaderCapRem`). Status/priority/due tones and helpers in `components/workMeta.ts`, shared chips in `WorkTaskBits.tsx`; every action goes through `useTaskActions` and every count through `taskRules` (`docs/features/tasks.md` → One task model). There is no live clock and no Now/Next timeline (`WorkDayTimeline` was removed on request; `useTimeBlocks` still feeds Daily's `DayAgenda`).
