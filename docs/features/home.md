Only placed sections mount. On a wide Home (board step ≥ 2) the Training, Books, Games and Watched tiles open their widget's content in a popup (`TileDetail`, whose "Open …" link replaces the popup's history entry); phones go to the page (Watched opens the title on the screen showing). Widgets use `WidgetShell` (on `Card`) + `useWidgetState` and **disable their queries when collapsed** (Training stays enabled — the brief reads the same data). Data comes only from hooks: `useWeather` (one query keyed by the real coordinates; refetches on focus and every 30 min — the installed PWA stays open for days; 24 hourly points, `hoursFromNow` drops the hours passed since the fetch), `useCurrencyRates` (`STALE.hour`, no focus refetch), `useNews`, `useWeekTrainingStats` (dated by `start_time`), `useTodayOverview` (task counts without cancelled; next-up/next-training include recurring blocks, calendar events and what's in progress), `useRecentlyWatched`, the Books reading hooks (`BooksHomeWidget.tsx`, the same numbers as Daily's Reading cell). The brief's Weather section says how the temperature goes from here in one sentence (`briefRules.temperatureOutlook`: the next few hours as a range, then cooling/warming to X° by HH:MM, "and it stays dry" when no rain is coming) instead of a separate "no rain" line.

- **Geolocation** (`useGeolocation.ts`): requests the browser's location once per session (`qk.external.geolocation()`, `STALE.never`; pull-to-refresh skips it), falls back to Oslo if denied/unsupported. `HomePage` calls it unconditionally so the prompt fires on load regardless of which widgets are mounted. Weather uses it for a real local forecast; Transit uses it for "📍 Nearby" real stops (only when the fix is real, not the Oslo fallback).
- **Weather** (`WeatherWidget.tsx` / phone tile → `WeatherDetails` popup, `useWeather` + `weatherApi.ts`): current conditions + detail row (pressure, cloud cover) + 12h hourly strip + 5-day forecast (`computeDailyForecast`, MET Norway compact product, midday-representative symbol per day).
- **Currency** (`CurrencyWidget.tsx` / phone tile → `CurrencyDetails` popup, `useCurrencyRates` + `currencyApi.ts`): **primary** NOK⇄TRY (direct — never routed through a third currency), **secondary** EUR⇄USD (their own parity), plus **gold** (XAU, confirmed available on the app's OXR plan via `/api/currencies.json`; shown as $/oz + NOK/gram with day-change badges). Replaced 5 confusing cross-rates that read as a wall of numbers.
- **Transit (`TransitPanel`, opened as a popup from Home's `TransitCard`)** — tabs **Routes** (default) · Departures · Settings. Routes = the planner: To home / To work (`ruter/PlaceButtons.tsx`, from Settings → Places), saved routes, "From here to" other saved stops, recent searches, From/To and an optional collapsed **Add a via stop** field (EnTur's `via` argument through `useTrips`; a via trip is neither recorded as a recent search nor saveable as a route — neither table has a via column). The separate Via tab is gone. Departures = the saved-stop board (saved + nearby stops, search, `QuaySavePanel`, directions). Supabase access lives in `api/transitStoreApi.ts`; reads in `hooks/useTransitQueries.ts` (keys from `qk.transit`/`qk.external`); every write (save/update/remove a stop, set default, add/remove a route) is a `useMutationWithFeedback` hook in `useTransitStops`/`useTransitRoutes`, and removals ask via `modal.confirm`. Line/brand colours are identity constants in `transitUtils`. Current behaviour + the verified-live gotchas:
  - Saving a stop: `SettingsTab` has its own **"Add a Stop"** section and Departures shares the same `QuaySavePanel.tsx` (extracted so the quay/direction/label flow isn't duplicated), with one-tap **🏠 Home / 💼 Work** presets and small bordered cards in a responsive grid. Both tabs show a **"📍 Nearby"** row from `ruterApi.fetchNearestStops` (EnTur's `nearest` root query — **verified live via GraphQL introspection before use**, per the no-speculative-schema rule).
  - **Quay identity (verified live at Visperud):** roadside stops have `publicCode` `""` (empty string, **not null**) AND a null description on every quay, so any code/description-based key merges distinct directions into one bucket. `DeparturesTab` groups by the quay's **raw NSR id**; `fetchDepartures` normalizes `""` → undefined at the boundary. `fetchStopDirections` collects ALL distinct destinations per quay (not just the first seen) and a shared `quayLabel()` renders them consistently in `QuaySavePanel`, `DeparturesTab` and `RoutesTab`'s `PlaceDisplay`.
  - **Filter at the DEPARTURE level, not the group level** — scoping a saved favourite's `quay_id` at group level meant the merged single group either matched wholesale or fell through to show-all. There's a "Show all directions" toggle and an honest "saved direction not found — showing all" state instead of a silent fallback.
  - **Migration `049`** widened `user_transit_stops`' unique index to include `quay_id` (saving two directions of the same physical stop used to hit a raw Postgres duplicate-key error); `useTransitStops.addStop` throws a typed `DuplicateStopError` the UI catches to offer `updateStop()` instead. Same migration added `lat`/`lon` so **address favourites** are saveable, gated behind an "Include addresses" checkbox (`StopSearchInput`'s `stopsOnly` prop).
  - `useTransitRecentSearches` wires up the previously-orphaned `transit_recent_searches` table (last 6 stop→stop searches, chips in `RoutesTab`). Geolocation auto-fills `RoutesTab`'s "From" once (never fights a manual clear). Favourite Routes in `SettingsTab` are clickable (`onSelectRoute` → `TransitPanel` switches to Routes and applies it once via `pendingRouteId`). `TripCard`'s summary shows an explicit "Leave in X min" / "Leave at HH:MM" instead of one ambiguous bold time; live line disruptions (EnTur `situations` on `line`) render as severity-coloured badges in `TripCard` + `DeparturesTab`. **Travel Profile** (`useTravelProfile`, localStorage like `useDayTargets`) persists walking pace / max transfers / wheelchair-accessible and is applied to every `fetchTrips()` via `TripPreferences`. The **via stop** (Routes) uses EnTur's verified `via: [TripViaLocationInput!]` argument (`gqlViaLocation()` builds `{visit: {stopLocationIds/coordinate}}`) and reuses `TripCard` unmodified — EnTur weaves the via stop into ONE coherent `TripPattern`.
  - **Real bug fixed:** `RoutesTab`'s "use current location" set an `'error'` state on GPS timeout/unavailable but rendered no message (only `'denied'` had visible text) — a silent failure violating the mandatory-toast rule; both paths now `toast.error(...)` on any geolocation failure.

## Home widgets

**Home widgets:** All use `WidgetShell` + `useWidgetState` and read data through `features/home/hooks/*`. Disable queries when collapsed.

## Daily brief (rule-based)

**Daily brief (Home) — rule-based, not AI (26.09.2026, user's call).** The old AI-written digest (`DailyBriefing`/`useDailyBriefing`/`briefingApi` + `fetchCurrencyWeekTrend`) was deleted and replaced by a deterministic brief: `briefRules.ts::buildDailyBrief(input)` (pure, import-free; `scripts/verify-daily-brief.cjs`, 74 assertions) turns already-loaded data into a greeting, ONE headline (priority: overdue tasks → in-progress block → training today (named) → next block → open tasks) and short sections, in this order — Tasks (counts + a focus task: overdue > priority > due time), Schedule (one line), Training, Weather (now + feels-like/wind when it matters, the rest of today, a rain window from the hourly forecast, tomorrow from 18:00), Food (kcal + protein on one line, water pace), Watch (the next episode of the Watching show touched last, and one released wishlist title picked by day of year — both open the popup), NOK → TRY (rate, 1,000 NOK, a plain comment on the move since yesterday). No wishes and no EUR/USD (owner, 05.10.2026). A section with nothing worth saying is omitted, never padded; the same data always gives the same text; no AI call and no cost. `useDailyBrief()` only gathers inputs from existing hooks (no queries of its own). The phone `brief` action (`phone-gateway` → `ai-proxy`) is separate and still AI.
