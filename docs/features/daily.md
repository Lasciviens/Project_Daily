# Daily

> Moved out of CLAUDE.md on 13.10.2026 (word for word, apart from translated quotes). This file describes how the feature works and why. The rules Claude must follow while changing it are in `.claude/rules/tasks.md`, which Claude Code loads by itself when a matching file is read or edited.

## Overview

See Daily section below. Four modes (Day/Week/Month/Tasks) + a glance board.

## Daily Feature Detail

`DailyPage.tsx` (`src/features/daily/pages/`) — `PageContainer width="wide"` + `PageHeader`: the date arrows sit in the title with the greeting/time as subtitle, and ONE `SegmentedControl` switches periods. **Four modes** (`type Mode = 'day' | 'week' | 'month' | 'tasks'`); the Yesterday/Today/Tomorrow highlight is DERIVED from `viewDate` (the three old near-identical day views are one `DaySection`). Desktop tabs: Yesterday · Today · Tomorrow · Week · Month · Tasks; mobile collapses to a 4-cell segmented control (Today · Week · Month · Tasks).

- **Day mode is a PageBoard** (`dailyBoards.ts` → `DAY_BOARD`): phones/tablets and 1280/1469 stack the day card then the glance board; 1920 puts the card across main + one side with **`DayQuickRail`** (quick actions, up to 3 next blocks, an entry into Tasks) beside it and the glance board below; 2450 puts the glance board beside the day card (3 columns) and the rail under it as one strip. The day card = `WeekStrip` (7 fixed day cells for the viewed week, chevrons browse without changing viewDate, cell click = view that day; each cell's number = the day's open tasks + the repeat days still to do on it; the full `WeekWidget` lives under the Week tab) → `DayAgenda bare` — the day as ONE list (below). A new item from a day gets that day as its date and `taskRules.sectionForDay`'s section: Today for today, Backlog for any other day.
- **`TodaySummary` (glance board)** — shown for EVERY viewed day, not just today. Columns follow the board's own width (`@container`): 1 / 2 / 3 / 4 at 36 / 55 / 90rem; each module is its own `Card`. **Nutrition is a double slot**; from three columns it is three rows tall, so the small cards stack beside it instead of stretching (2 columns: N N / T W / H G / S B; 3 columns: N N T / N N W / N N H / G S B; 4 columns: N N T W / N N H G / N N S B — every grid full). Where the board sits beside the schedule (`DAY_BOARD` step 4, `glanceInColumn`) its heading is visually hidden. **NO auto-fill anywhere and explicit column counts only** — the user requires boxes never to change position based on content/size (verified by E2E: cell x/w identical between a full and an empty day). Cells share `summary/cellKit.tsx` anatomy (Cell / CellHeader icon-chip / CellLink). An empty module collapses to a compact row IN PLACE; it never leaves its slot. Cards: **NutritionCard** (double slot, see below), **TrainingCard** (planned/done; on a rest day it lists Hevy routines INLINE and plans one through the `time-block` popup with its `training_session` source, prefilled for the viewed date), **WatchNextCard** (chip-switch between watching/paused series, real next-unwatched episode from `useNextEpisode`, SxxEyy + title + watched count + future-air-date badge, Watched (`useMarkEpisodeWatched`) auto-advances, Plan opens the `time-block` popup with the episode on its source), **HealthCard** (swipeable sleep/steps/energy/heart/weight strip reusing the Health aggregation), **GamesCard**, **ShopCard**, **ReadingCard** (minutes on the viewed day vs the reading goal, the streak, the book in hand; a day the Kobo has not reported reads "Not synced yet"). Work + Projects cards were removed (they have their own pages).
- **`NutritionCard` = Nutrition + Meals merged into one card** (the separate `summary/MealsCard.tsx` was deleted). It carries: the meal timeline (slots Breakfast · Lunch · Dinner · Snack · Suppl., each with its emoji as content, current slot highlighted on today; planned rows muted/italic) with per-row edit (`food-log-edit` / `meal-plan` popup) / confirm-planned / delete icon buttons (a dish — rows sharing a `meal_group_id` — is ONE line since 16.10.2026: its name, item count and kcal; ✎ opens Edit meal, ✕ deletes the meal; `docs/features/food.md`, Diary round), per-slot **free-text quick-add** (live data showed usage is ~100% custom titles; an exact/start-of-name library match auto-logs with real macros, a loose match opens the `food-log` popup with `query` prefilled), recent-food chips (`useRecentFoods`, diary-sourced, re-log their own snapshot), copy-yesterday into empty slots, the calorie ring + protein/macros, `GoalSummary` (Edit goal opens the `day-targets` popup), and **`WaterTracker`**.
- **`DayAgenda` — the day as ONE list (owner, 15.10.2026: "one item").** It replaced two panes side by side — Schedule (slots, repeating plans, Google events, with **Add**) and Tasks (`DayView`, with **Add task**) — in which a task with its slot showed twice and a day of a repeat could not be ticked. The rows come from the pure `daily/dayItems.ts` (`buildDayRows`, `verify-day-items`) over the reads the day already had: the day list (`useDayTasks` — nothing filtered, NEVER_HIDES), the one day schedule (`daySchedule.buildDaySchedule`: slots and yesterday's tails, repeating plans, Google events the app didn't make) and, by id, the tasks of the day's slots whose date is another day. Rules:
  - **Split by TIME, never by table.** Phone and any card under 54rem: **Anytime** first (all-day Google events lead it, then the open tasks and repeat days with no time — the open-wishes row sits above it), then **Schedule** (every row with a time, in time order, with the now-marker on today; "· Nh planned" counts only what holds time), then **Done** and **Cancelled** (untimed ones only). From a 54rem card (laptop): the Schedule column beside an Anytime column with Done and Cancelled under it (capped at 38rem / 34rem from 72rem). The parts are one DOM list; the right-hand wrapper is `display: contents` on the phone so CSS `order` puts Anytime first. An empty part leaves no line on the phone and keeps its heading ("Nothing at a set time") as a column.
  - **A task with its slot on this day is ONE row**, at the slot's time (the shared `ToDoItem` beside a time gutter: start, end, the slot's colour tag, an overlap ⚠). A task with a time and no slot sits at that time as a moment (no end — "at 14:00" holds no time, decision 3); a task with no time is Anytime; an overdue task's old time is not today's time (Anytime). A slot whose task is due on another day still ticks (its task is read by id).
  - **A day of a repeating plan is a row with the Repeat mark** and its own tick: tick = done for that day, ⋯ → Skip this day, and on a done / skipped day Not done / Undo skip — all through `useRepeatDay()` (it says "Done for 15.10.2026 · Undo"). A day nobody acted on is the plan's projection — since 156 together with its **day's task** (made on its day, `tasks.schedule_block_id` + `occurrence_date`): ONE row holding the task, its state the task's (done, skipped, missed), never a task row beside it; a day acted on is 142's one-off task + slot (`time_blocks.schedule_block_id` + `occurrence_date`, the plan's `except_dates`) and still reads as the plan's day, and a day's task moved off its day is a repeat row on the day it is now. A repeat with no time (155) is an Anytime row; a repeat at a time with no length is a moment. Tapping a day nobody acted on opens the plan's sheet with `occurrenceDate` (This day / All days); an acted-on day opens its task.
  - **A ticked timed row stays dimmed in its slot**; a skipped day reads **Skipped** there. **A day of a repeat that passed with no tick stays on its day as Missed** (never carried over — since 156 the database closes its day's task as missed on its own day: `cancelled` + `closed_reason 'missed'`, so it is neither overdue nor on Today's lists afterwards); the header counts it as "N missed", not open. Week and month counts don't count it either (a count can't see a training day a workout already covered).
  - **Training** rows keep the session's own status pill and ⋯ (`TrainingPlanMenu`) and open the session popup; their tick is the session's Mark done / Reopen (`useTrainingPlanActions`), disabled when a Hevy workout did it.
  - **Google events the app didn't make** keep their own rows with the calendar mark and no tick (they open `EditCalendarEventModal`); an event the app made is its row's (`daySchedule` de-dupes by id and `recurringEventId`). **A slot with no task** (made before "Convert old items", Settings → Subscriptions → Google) has no tick; ⋯ → 30 minutes later / Move to the next day / Edit / Delete (asks, Undo). The tail of yesterday's slot or plan after midnight is a "continued" row that opens the same thing.
  - **One Add** in the header (and Morning / Afternoon / Evening chips on an empty day) opens the one sheet (`useEntityModal().open({ kind: 'task', defaults })`) with the day as its date (`date`, `dueDate`, the day's section; a chip adds `startTime` + `scheduled`). The header: "Day plan", N open (the day list's open tasks + the repeat days still to do that are not tasks yet — `repeatDayKeys`, so today's repeats count once), N done, N missed, and "Next: … at HH:MM" / "Now: … until HH:MM" from `daySchedule.aheadOnDay`; the Google sync button when Calendar is connected.
  - Rows are 44px for one line (the tick's and ⋯'s tap areas reach into the row padding); custom rows copy `ToDoItem`'s anatomy (tick · title · pills · ⋯) so the list reads as one. The old Night group and the "No time set" group are gone: the gutter shows 03:00 as it is, and a slot with no time is Anytime.
- **Week and Month** share `PICKER_SECTIONS`: picker (40rem — `WeekWidget` / `MonthWidget big`) + the picked day in place — one pane (picked day or Upcoming) at 1280/1469, the picked day's list + Upcoming at 1920, the picked day two tracks wide at 2450 (its list is the one day list — the separate "Tasks · <day>" card went with the merge, 15.10.2026); on phones/tablets the week strip opens the day, on wider pages it picks in place. Every day number and the week's open / % done include the repeat days still to do from today on (a ticked one is its own task); the month puts a dot on every day a repeat falls on (a missed one too) and its "N open" adds the month's repeat days still to do. The picked-day card shortens its date when it has two buttons; Daily's header is capped to the mode's board width (`boardWidthRem`). **Tasks mode** = `TasksPanel` (all tasks): one card on phones, columns on wider pages — overdue · open now · today | upcoming | no date | done today (`taskRules.taskGroups`; Today = the day pane's own list, so an undated task in the Today section is under Today, not No date); an empty column keeps its heading with a 0 badge.
- **Cancel** (⊘, `ToDoItem`/`WorkTaskCard`) sets `status='cancelled'` — `TaskStatus` always had the value but no UI ever set it; distinct from Delete (keeps a record instead of destroying the row). Daily's day list has a "Cancelled" part (cancelled on that day, like Done; a timed one stays dimmed in its slot) so a cancelled task stays visible; the Work board has no cancelled column, so there it simply drops off (matches the "cancelled excluded from active counts" convention used everywhere — WeekWidget/MonthWidget/HomePage/…).
- **`ToDoItem`'s desktop action row (✎/↳/📋/⊘/✕) and the checkbox both silently no-opped into opening the edit modal instead — a real bug in `useSwipeToReveal.ts`, not in `ToDoItem` itself.** `onPointerDown` called `e.currentTarget.setPointerCapture(e.pointerId)` **unconditionally**, on every pointerdown anywhere inside the row — including one that started on a nested interactive child (pointerdown bubbles up regardless of which descendant it began on). Once a pointer is captured, the browser retargets that pointer's subsequent `pointerup` **and the `click` it synthesizes** to the CAPTURING element (the row), never wherever the pointer physically is — so a plain tap on the checkbox or any of the five action buttons fired the ROW's own `onClick` (open edit) instead of the button's own handler: the checkbox never toggled, Delete never deleted, Cancel/Reopen never updated status, and every action looked identical from the outside ("everything opens edit"). The mobile `⋯` menu was unaffected because Headless UI's `MenuItems` portals outside the row's DOM subtree, so its clicks never bubble through this handler at all — this made the bug desktop-only, exactly where it was reported. Fixed by deferring `setPointerCapture` out of `onPointerDown` and into `onPointerMove`, firing only once a genuine horizontal swipe is confirmed (`axisLocked.current === 'x'`) — a plain tap never moves enough to reach that branch, so its click reaches its real target untouched; only an actual swipe gesture (which still needs capture to survive the pointer leaving the row's bounds mid-gesture) ever captures the pointer. `ToDoItem` opens its editor as the `task` popup (rows no longer each mount a hidden editor), keeps its action menus in `ToDoItemActions.tsx`, and toasts nothing itself — the migrated task hooks own error feedback (Delete asks, then says "Task deleted · Undo" — `docs/features/delete-undo.md`).
- **The `section` day-leak (real bug, fixed on the READ side only).** Daily once mapped a whole range of days onto one `section` (+2…+7 → `this_week`, the rest → `backlog`) and read undated rows of that section on each of them, so one undated row showed on six days. Only Today keeps undated rows now (`taskRules.onDay`; see `docs/features/tasks.md` → **One task model**); no row was rewritten and `section` stays (dropping it breaks 037's audit list, 046's policies and `DB_CATALOG`, and both possible backfills manufacture wrong dates). Undated rows still reach the Tasks tab's "No date" group, the open undated ones of this week the day list's folded "This week — no date" band (`DayAgendaExtras.tsx`). `TaskTab`'s `SECTIONS` also dropped the `Tomorrow`/`This Week` pills (neither has a home of its own — picking one only made a task float like Backlog under a date-shaped name). Since 13.10.2026 the app no longer writes either value: `taskRules.sectionForDay` (a new task from Daily's day view) and `planModal.config`'s `sectionForDate` ("Also add to Tasks", Training's planned task) give Today for today and Backlog for any other day — a new task from the Tomorrow tab used to open with "Tomorrow (legacy)" selected. Backlog keeps a future task out of today's server-side `section.eq.today` lists exactly as Tomorrow / This week did; on its day it shows by its due date. Since 14.10.2026 (owner: "Remove that Tomorrow button") there is no "(legacy)" pill either: a row still holding a retired value opens with Backlog picked and Save writes Backlog (`taskRules.liveSection`); the planner's form, its defaults and the task create/update inputs take `LiveTaskSection` (`inbox|today|backlog`), so no caller can pass one, and the assistant's `db_insert`/`db_update` refuse them (its "plan a watch" tool files Today/Backlog since 13.10.2026). **A new item's date must keep defaulting to today** (`planForm.ts`; since one item, 155, the section follows the date — no date → Inbox) — four server-side `section.eq.today` predicates (`phone-gateway` ×2, `push-send`, `ai-proxy`) drain silently if new items land undated in the Inbox, quietening the brief and the lock-screen push forever.
