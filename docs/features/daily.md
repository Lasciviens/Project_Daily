# Daily

## Overview

See Daily section below. Four modes (Day/Week/Month/Tasks) + a glance board.

## Daily Feature Detail

`DailyPage.tsx` (`src/features/daily/pages/`) — `PageContainer width="wide"` + `PageHeader`: the date arrows sit in the title with the greeting/time as subtitle, and ONE `SegmentedControl` switches periods. **Four modes** (`type Mode = 'day' | 'week' | 'month' | 'tasks'`); the Yesterday/Today/Tomorrow highlight is DERIVED from `viewDate` (the three old near-identical day views are one `DaySection`). Desktop tabs: Yesterday · Today · Tomorrow · Week · Month · Tasks; mobile collapses to a 4-cell segmented control (Today · Week · Month · Tasks).

- **Day mode is a PageBoard** (`dailyBoards.ts` → `DAY_BOARD`): phones/tablets and 1280/1469 stack the schedule card then the glance board; 1920 puts the card across main + one side with **`DayQuickRail`** (quick actions, up to 3 next blocks, an entry into Tasks) beside it and the glance board below; 2450 puts the glance board beside the schedule (3 columns) and the rail under it as one strip. The schedule card = `WeekStrip` (7 fixed day cells for the viewed week, chevrons browse without changing viewDate, cell click = view that day; the full `WeekWidget` lives under the Week tab) → `DayAgenda bare` | `DayView`, side by side once the card is 54rem wide (a landscape phone stacks); from 72rem the panes are capped at 40rem and 36rem. Both panes have the same header — label and counts on the left, the pane's primary add in the right corner (Schedule's **Add**, Tasks' **Add task**; owner, 13.10.2026) — so the two adds sit on one line side by side and in the same place when stacked; the open-wishes row sits under the Tasks header. A new task from a day gets that day as its due date and `taskRules.sectionForDay`'s section: Today for today, Backlog for any other day.
- **`TodaySummary` (glance board)** — shown for EVERY viewed day, not just today. Columns follow the board's own width (`@container`): 1 / 2 / 3 / 4 at 36 / 55 / 90rem; each module is its own `Card`. **Nutrition is a double slot**; from three columns it is three rows tall, so the small cards stack beside it instead of stretching (2 columns: N N / T W / H G / S B; 3 columns: N N T / N N W / N N H / G S B; 4 columns: N N T W / N N H G / N N S B — every grid full). Where the board sits beside the schedule (`DAY_BOARD` step 4, `glanceInColumn`) its heading is visually hidden. **NO auto-fill anywhere and explicit column counts only** — the user requires boxes never to change position based on content/size (verified by E2E: cell x/w identical between a full and an empty day). Cells share `summary/cellKit.tsx` anatomy (Cell / CellHeader icon-chip / CellLink). An empty module collapses to a compact row IN PLACE; it never leaves its slot. Cards: **NutritionCard** (double slot, see below), **TrainingCard** (planned/done; on a rest day it lists Hevy routines INLINE and plans one through the `time-block` popup with its `training_session` source, prefilled for the viewed date), **WatchNextCard** (chip-switch between watching/paused series, real next-unwatched episode from `useNextEpisode`, SxxEyy + title + watched count + future-air-date badge, Watched (`useMarkEpisodeWatched`) auto-advances, Plan opens the `time-block` popup with the episode on its source), **HealthCard** (swipeable sleep/steps/energy/heart/weight strip reusing the Health aggregation), **GamesCard**, **ShopCard**, **ReadingCard** (minutes on the viewed day vs the reading goal, the streak, the book in hand; a day the Kobo has not reported reads "Not synced yet"). Work + Projects cards were removed (they have their own pages).
- **`NutritionCard` = Nutrition + Meals merged into one card** (the separate `summary/MealsCard.tsx` was deleted). It carries: the meal timeline (slots Breakfast · Lunch · Dinner · Snack · Suppl., each with its emoji as content, current slot highlighted on today; planned rows muted/italic) with per-row edit (`food-log-edit` / `meal-plan` popup) / confirm-planned / delete icon buttons, per-slot **free-text quick-add** (live data showed usage is ~100% custom titles; an exact/start-of-name library match auto-logs with real macros, a loose match opens the `food-log` popup with `query` prefilled), recent-food chips (`useRecentFoods`, diary-sourced, re-log their own snapshot), copy-yesterday into empty slots, the calorie ring + protein/macros, `GoalSummary` (Edit goal opens the `day-targets` popup), and **`WaterTracker`**.
- **`DayAgenda`** replaced the old 24h×52px pixel-grid `DayTimeline` (deleted): dense agenda rows (time · duration · title · lucide recurring / calendar / overlap / spillover badges, block colour tags mapped to tones; +30m/+1d/rename/delete quick actions behind a ⋯ toggle), a Night group for blocks before 06:00, a now-marker (the "Nh free · +" gap rows were removed on request), NULL-`start_time` blocks in a "No time set" group (real data has them), empty-day quick-add chips (Morning/Afternoon/Evening). Every editor opens through `useEntityModal` (`time-block` to add or edit a one-off row, `task` for a task-linked row, `schedule-block` for recurring, `EditCalendarEventModal` — edit-only, on `ModalShell` — for Google events); linked-task notes come from `useTasksByIds`. Drag-to-reschedule was dropped with the grid.
- **Week and Month** share `PICKER_SECTIONS`: picker (40rem — `WeekWidget` / `MonthWidget big`) + the picked day in place — one pane (picked day or Upcoming) at 1280/1469, the picked day's schedule + Upcoming at 1920, plus that day's tasks ("Tasks · <day>") at 2450; on phones/tablets the week strip opens the day, on wider pages it picks in place. The picked-day card shortens its date when it has two buttons; Daily's header is capped to the mode's board width (`boardWidthRem`). **Tasks mode** = `TasksPanel` (all tasks): one card on phones, columns on wider pages — overdue · open now · today | upcoming | no date | done today (`taskRules.taskGroups`; Today = the day pane's own list, so an undated task in the Today section is under Today, not No date); an empty column keeps its heading with a 0 badge.
- **Cancel** (⊘, `ToDoItem`/`WorkTaskCard`) sets `status='cancelled'` — `TaskStatus` always had the value but no UI ever set it; distinct from Delete (keeps a record instead of destroying the row). `DayView` has a "Cancelled" section (cancelled on that day, like Done) so a cancelled task stays visible; the Work board has no cancelled column, so there it simply drops off (matches the "cancelled excluded from active counts" convention used everywhere — WeekWidget/MonthWidget/HomePage/…).
- **`ToDoItem`'s desktop action row (✎/↳/📋/⊘/✕) and the checkbox both silently no-opped into opening the edit modal instead — a real bug in `useSwipeToReveal.ts`, not in `ToDoItem` itself.** `onPointerDown` called `e.currentTarget.setPointerCapture(e.pointerId)` **unconditionally**, on every pointerdown anywhere inside the row — including one that started on a nested interactive child (pointerdown bubbles up regardless of which descendant it began on). Once a pointer is captured, the browser retargets that pointer's subsequent `pointerup` **and the `click` it synthesizes** to the CAPTURING element (the row), never wherever the pointer physically is — so a plain tap on the checkbox or any of the five action buttons fired the ROW's own `onClick` (open edit) instead of the button's own handler: the checkbox never toggled, Delete never deleted, Cancel/Reopen never updated status, and every action looked identical from the outside ("everything opens edit"). The mobile `⋯` menu was unaffected because Headless UI's `MenuItems` portals outside the row's DOM subtree, so its clicks never bubble through this handler at all — this made the bug desktop-only, exactly where it was reported. Fixed by deferring `setPointerCapture` out of `onPointerDown` and into `onPointerMove`, firing only once a genuine horizontal swipe is confirmed (`axisLocked.current === 'x'`) — a plain tap never moves enough to reach that branch, so its click reaches its real target untouched; only an actual swipe gesture (which still needs capture to survive the pointer leaving the row's bounds mid-gesture) ever captures the pointer. `ToDoItem` opens its editor as the `task` popup (rows no longer each mount a hidden editor), keeps its action menus in `ToDoItemActions.tsx`, and toasts nothing itself — the migrated task hooks own error feedback (Delete asks, then says "Task deleted · Undo" — `docs/features/delete-undo.md`).
- **The `section` day-leak (real bug, fixed on the READ side only).** Daily once mapped a whole range of days onto one `section` (+2…+7 → `this_week`, the rest → `backlog`) and read undated rows of that section on each of them, so one undated row showed on six days. Only Today keeps undated rows now (`taskRules.onDay`; see `docs/features/tasks.md` → **One task model**); no row was rewritten and `section` stays (dropping it breaks 037's audit list, 046's policies and `DB_CATALOG`, and both possible backfills manufacture wrong dates). Undated rows still reach the Tasks tab's "No date" group, undated `this_week` ones `DayView`'s "This week — no date" band. `TaskTab`'s `SECTIONS` also dropped the `Tomorrow`/`This Week` pills (neither has a home of its own — picking one only made a task float like Backlog under a date-shaped name). Since 13.10.2026 the app no longer writes either value: `taskRules.sectionForDay` (a new task from Daily's day view) and `planModal.config`'s `sectionForDate` ("Also add to Tasks", Training's planned task) give Today for today and Backlog for any other day — a new task from the Tomorrow tab used to open with "Tomorrow (legacy)" selected. Backlog keeps a future task out of today's server-side `section.eq.today` lists exactly as Tomorrow / This week did; on its day it shows by its due date. Since 14.10.2026 (owner: "Remove that Tomorrow button") there is no "(legacy)" pill either: a row still holding a retired value opens with Backlog picked and Save writes Backlog (`taskRules.liveSection`); the planner's form, its defaults and the task create/update inputs take `LiveTaskSection` (`inbox|today|backlog`), so no caller can pass one, and the assistant's `db_insert`/`db_update` refuse them (its "plan a watch" tool files Today/Backlog since 13.10.2026). **`planForm.ts`'s `section: 'today'` default must NOT be changed** — four server-side `section.eq.today` predicates (`phone-gateway` ×2, `push-send`, `ai-proxy`) drain silently if it becomes `'inbox'`, quietening the brief and the lock-screen push forever.
