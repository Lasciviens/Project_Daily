# Dev Requests

> Moved out of CLAUDE.md on 13.10.2026 (word for word, apart from translated quotes). This file describes how the feature works and why. The rules Claude must follow while changing it are in `.claude/rules/dev-requests.md`, which Claude Code loads by itself when a matching file is read or edited.

## Overview

**The live backlog.** A `SideDrawer` opened from the Requests button in the top bar / phone header; jot bugs/features/improvements/integration ideas/long-term wishes about the app itself. `dev_requests` (migration `042`, owner-only RLS, `user_id DEFAULT auth.uid()`): title, description, `page` (a dropdown from the nav registry — `PAGE_CHOICES` in `devRequestMeta.ts`; an old free-text value stays selectable), `category`, `priority`, `status` (open/in_progress/done/dismissed), `effort`, `sort_order` (a new request goes on top, min − 1). See **Dev Requests Feature Detail** below.

## Dev Requests Feature Detail

**29.09.2026 round:** the floating composer is the ONLY editor (tapping a card opens it; the inline forms and `DevRequestForm.tsx` are gone; status is a select in the composer). The card's circle is a checkbox feeding one selection → action bar (Mark done · Delete · Build prompt). Cards show "Added … · Done …" (`completed_at`, trigger-stamped, migration `114`) and a warn "Prompted" pill once a prompt was built/copied (`prompted_at`). **06.10.2026 round 2 (owner's spec):** **one box is the outline** — the request window's text box (`OutlineEditor` + `OutlineRow`, one small contenteditable per point holding text and pick-link chips) numbers points live, 1, 2 … and sub-points 1.1, 1.2 …: Enter new point, Shift+Enter line break, Tab / Shift+Tab sub-point / point (also buttons in the box's toolbar for phones), Backspace at the start outdents then joins the point above, Delete at the end pulls the next point in, arrows cross points at their edges, pasted blank-line-separated blocks become points. **Storage** (plain text in `description`, `outline.ts`): a blank line between points, a sub-point block starts with two spaces, a single newline is a line break inside a point; a re-check point keeps its "Still not fixed: …" line as its tail; old paragraphs, `1- ` lines and `- [ ]` checkpoints still read and `descriptionForSave` rewrites them as a clean outline (a tick becomes a Fixed review). Review keys hash a point's words only, not its indent or number. **The request window is where work is checked:** once prompted (or in progress / done) each point row has ✓ / ✗ (success / danger) and a "What is still wrong?" note, a moved point links to its re-check, and a "Check the work" bar shows a meter + "2 of 5 fixed · 1 not fixed · 1 moved", Send N not fixed to re-check and Mark request done. The drawer card is a summary only (title, page, preview, pills, progress meter, dates, Prompted, selection — no point buttons). Re-check requests open with a "Re-check of <original> ↗" block and each point shows a "Still not fixed" callout; a sub-point sent to re-check carries its parent's first line. **The prompt is its own step:** Build prompt switches the window to "Prompt for Claude" (← back, included requests, Change, editable text, Reset, Copy); the request window has no Prompt tab. Prompt shape: `## Request N — Title`, a meta line, points `1.` / `1.1` as in the editor, `[already fixed]` / `[moved]` one-liners, NOT FIXED notes, RE-CHECK lines, `[n]` footnotes, and only the "How to work" rules that apply. With more than one point, one rule asks the agent to group the points by the area and files they touch, do connected points together so nothing finished is reopened, and list the groups and their order first (owner, 14.10.2026). **Window:** resizes on tablet/desktop from its right edge, bottom edge and bottom-right corner (360×420 up to the screen; request and prompt keep their own size per device; double-clicking the title bar resets position and size — `composer/windowSize.ts`, `useWindowResize.ts`); details are pill buttons (Status, Category, Priority, Page, Effort) that each open a dropdown over the content — nothing moves, no new line (13.10.2026, owner: "should be dropdown instead of opening a new line"; before, a tap opened an option tray on a new line under the pills). `PropertyPills` is a Headless UI `Listbox` per pill with `modal={false}` (no scroll lock, nothing made inert) and **no `anchor`**: an anchored list is always portalled into `#headlessui-portal-root`, onto the menu layer — behind the window (`z-float`) and behind any popup open under it — and outside `data-dev-request-ui`. The list stays in the window's DOM and is placed `position: fixed` at its pill (`propertyPillsPlacement.ts`: below when it fits or there is more room below, else above; capped at 20rem and to the room on that side, the rest scrolls; re-placed on scroll/resize), so the window's scroll area doesn't clip it. Keys: Space or ↓ opens, arrows move, Enter picks, Esc closes the list only. The pills show on every screen, phones too, right under the points (14.10.2026, owner: the phone's "Details" fold is gone — a property is one tap, not two); footer Delete / Discard / "Unsaved · kept on this device" / Save; Ctrl/⌘+Enter saves (28.10.2026: not again while a save is on its way or from a held key — it made duplicates). Pure: `outline.ts`, `pointText.ts`, `points.ts`, `devRequestPrompt.ts`, `windowSize.ts`, `propertyPillsPlacement.ts`. No migration. **Picks are links in the text (29.09.2026, owner's spec):** Pick on page (or Alt-click / Quote selection) puts a blue underlined link where the caret was ("I want **Water card** to be red") — `LinkedTextEditor` (a contenteditable box; value = plain text with `[[@id]]` tokens, rendered as atomic `<span data-ref>` links; Enter/paste go through the value, DOM helpers in `linkedTextDom.ts`). The link's data is one hidden line `[[pick {id, label, capture}]]` (`insertPickLink`, `linkLabel`: the card a heading names → "Water card", else the control's label, else the humanized component); deleting the link drops its pick on save (`descriptionForSave`). Clicking a link (in the composer or on the card, which shows the text with its links) runs **Go there** (`pick/goToMark.ts`: navigates to the stored route + query, closes the drawer, finds the element by its `data-src` stamps + label, reopens the popups it sat in, outer → inner — an entity popup from its saved request, a local one by clicking what opened it (`shared/modals/popupTrail.ts`: every open `ModalShell` registers its request or its trigger; `readPopupTrail` stores them in the capture's `popups`) — then looks only inside the top popup, scrolls to the spot and gives it a red glowing border that pulses twice, `.goto-blink` in index.css; a popup that can't be reopened is named in a toast and nothing behind it is outlined). The saved page context `[[page {json}]]` stays out of sight. The prompt builder turns each link into `“Water card” [1]` with footnote [1] carrying the full detail (`markPromptText`: component + file, route with query, element, text, value, page tabs, popup, where, screen) and lists checkpoints as numbered sub-points (`1.2 [done] …`). Old requests still render: id-less picks show as rows with Go there, `[Picked …]`/`[Page context]` blocks read as legacy marks (kept verbatim for the prompt), old `1- ` points stay body text (still numbered in the prompt). A Vite plugin (`pick/componentSourceTransform.ts`, `DEV_SRC_STAMP=0` disables) stamps `data-src="src/…/File.tsx#Name"` on every app component's root element (+1.7 % bundle). Older notes below that mention inline forms or status cycling are superseded.

`src/features/devRequests/`. **Nothing typed is ever lost:** `SideDrawer` unmounts its content on close, and the old form kept its text in component state, so a click outside, Esc or Back threw a half-written request away. Every draft now lives in `devRequestDraftStore.ts` — Zustand persisted to localStorage key `lasci.devRequests` (this device only, owner decision; writes debounced 300 ms and flushed on `pagehide`/hidden, every access guarded, read back field by field through `sanitizeDraftState`). It holds the new draft (with the page it was started on), unsaved edits per request (a card shows "Unsaved edits"; Close keeps them, Discard drops them with an Undo toast), the composer, the drawer's filters/sort/"Completed" expansion/open form/pick selection, and the prompt.
- **Drawer:** multi-select category filter + manual/priority sort, inline edit, status cycles open → in_progress → done on click; done items collapse into "Completed (N)" with **Delete all closed** (done + dismissed, confirmed).
- **Floating composer** (`composer/`, mounted by `DevRequestComposerHost` in `router.tsx` beside `<Routes>`, so it survives every navigation; its code loads only once opened). One request (new, or an edit popped out of the drawer) plus the prompt, in **Request | Prompt** tabs. Tablet/desktop: a draggable window (`useFloatingWindow` — title bar drags, kept on screen, re-clamped on resize, Alt+Arrow nudges, double-click resets to the corner, position persisted), minimisable to a pill bottom-right. Phones: docked above the tab bar (lifted above the keyboard), collapsing to a pill. "New" opens it on tablet/desktop; phones get the inline form + a Pop-out button (owner decision). A right-edge drawer (Requests, Ask AI) tucks the window away until it closes; Esc inside it minimises. **Never a Dialog:** it is a direct child of `<body>`, which Headless UI does not make inert, so it stays usable over popups (`z-float` 150) and clicks in it are not "outside" clicks for an open popup.
- **Pick on page** (`pick/usePickMode.ts`, `pickDom.ts`): capture-phase listeners on `window` swallow the picking click before any page handler, drawer backdrop or Headless UI outside-click runs (no overlay element, so hover and scrolling keep working). Desktop: click picks, ↑/↓ widen/narrow, Esc stops, **Alt-click** picks any time the composer is open. Phones: tap selects, then Wider / Use this. **Quote selection** adds the selected text. On save, a new request also gets a page mark (page + query, heading, selected tabs, open popup, screen/breakpoint/theme, bundle name, start time) unless "Attach page context" is unticked. No migration: context is text in `description` (owner decision).
- **Prompt for Claude:** pick requests in the drawer (two-line preview of each description) → Build prompt → the window's prompt mode: an editable textarea (edits persist), Copy, Reset to generated, the included requests and Change selection. Building again over an edited prompt asks first.
- **Drag reorder** renumbers the whole list (`planReorder`) and writes only changed rows (the old optimistic update replaced the cache with just the dragged, filtered rows).
- Pure modules `devRequestContext.ts` / `devRequestRules.ts` / `devRequestPrompt.ts` and `clampPosition` (+ `devRequestMarks.ts`, `checkpoints.ts`) (+ `outline.ts`, `pointText.ts`, `points.ts`, `windowSize.ts`, `propertyPillsPlacement.ts`) are verified by `scripts/verify-dev-request-context.cjs` (358 assertions).
