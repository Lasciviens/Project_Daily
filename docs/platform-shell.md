# Platform, shell and routes

> Moved out of CLAUDE.md on 13.10.2026 (word for word, apart from translated quotes). This file describes how the feature works and why. The rules Claude must follow while changing it are in `.claude/rules/shell.md`, which Claude Code loads by itself when a matching file is read or edited.

## Platform & Shell

**PWA / service worker — updates arrive at a quiet moment (12.10.2026).** History: `registerType: 'autoUpdate'` with no update logic left a new worker waiting until every tab closed, so a shipped fix stayed invisible; the July fix (`skipWaiting` + `clientsClaim` + an automatic reload) then reloaded the page whenever a deploy's worker was ready: right after opening the app and in the middle of work (owner report). Now `vite.config.ts` uses `registerType: 'prompt'` (no `skipWaiting`, `clientsClaim: true`) and `src/app/serviceWorkerUpdate.ts` registers the worker: a new version installs in the background and WAITS (the old worker keeps serving the open page's own files, so a late chunk never 404s), then takes over and reloads once only when the app is in the background or untouched for 10 minutes, never with a dialog open or text in a field (pure rules `src/app/swUpdateRules.ts`, `verify-sw-update`). An app left open asks for a new version every 30 minutes and on return after 15 minutes away. So a deploy shows up the next time you switch away and come back. The service worker caches no Supabase responses (the old `supabase-api` cache is deleted once on start). Sign-out (`src/security/accountState.ts`) also deletes its runtime caches that say something about you — `weather-api` (location), `transit-api` (stop searches), `tmdb-images` — and the old `supabase-api`; the device copy of the body goals stays (it can be the only copy). Since 28.10.2026 it also clears the Google calendars picked (`calendar-token`'s `selectedCalendarIds` — the main calendar's id is the account's address), the IGDB review list (`lasci.igdbBatch`) and the Games auto-sync marks (`lasci.games.autoSync.*`); typed drafts stay — Dev Requests and a Shop chain being built (`lasci.shop.chainDraft*`), as a session that expires lands there too (`verify-calendar-recurrence`, "sign-out"). **Pages load on demand** (`src/app/pages.ts`, `lazyPage`): the first download is the shell and the opened page (301 KB gzipped, was 1054 KB with every page in one 2.7 MB file); the other pages' code loads in idle time after start (`preloadPages` from `AppShell`), and a preloaded page renders with no Suspense fallback. A new page goes in `pages.ts` (and its `PRELOAD_ORDER`), not as a static import in the router.

**App shell** — `src/app/shell/` (`layout.tsx` is gone). `AppShell` (one tree for every breakpoint, so rotation/resize never remounts the page) mounts `AppSidebar` (232px with group labels from 1280px, a 68px icon rail from 768–1279px) + `AppTopBar` (route title, search trigger, Ask AI, Requests, `SettingsMenu`) on tablet/desktop, `MobileHeader` + `BottomTabBar` + `MoreSheet` on phones (< 768px or a landscape phone — `useBreakpoint()`), plus `DevRequestsDrawer`, `AIPanel` (both on `SideDrawer`: right edge, a draggable bottom sheet on phones), `CommandBar` and the one `ModalHost`. On desktop the sidebar has a footer toggle (Collapse/Expand sidebar), saved in `useSidebarStore` (`app-sidebar`); a registry entry flagged `collapseSidebar` (Games) opens with it folded every time, and the toggle there doesn't change the saved preference. Toasts sit right of the rail whenever it is folded. **`src/app/navigation.ts` is the ONE nav registry** — sidebar, header titles, tab bar, More sheet, command bar and Dev Requests' page list all read it; adding a page = one entry there. `useAppBootstrap()` holds app-wide side effects (today: the Calendar token refresh). A route change resets `main.scrollTop` (restores it on Back/POP), resets the chrome and **closes the whole popup stack**. **The shell's title is the ONLY visible page name** — `PageHeader`'s `title` is a screen-reader-only h1 at every width (`showTitle` only when the title is content, e.g. Daily's date nav); with no visible title, children and actions share the first row (THEME.md §6.2). Each bullet below is a device-verified gotcha:
- **The document NEVER scrolls** — `html/body/#root` are fixed-height (index.css) and `<main data-app-scroller>` (AppShell) is THE scroll container. This is what made custom pull-to-refresh reliable on a real iPhone: with the document as scroller, iOS decides gesture ownership on the FIRST touchmove — one uncancelled move commits the root rubber-band and flips `e.cancelable` false for the rest of the gesture, so the pull only worked when the first move happened to be cleanly downward.
- `usePullToRefresh` has a slop + axis-lock state machine (horizontal swipes on snap strips are never hijacked; pull distance re-anchors at commit) and an `isReady` state (indicator flips to solid accent = "release to refresh").
- **Tab navigation slides directionally:** BottomTabBar passes `forward`/`back` (tab order) → `useViewTransitionNav` stamps `data-vt-dir` on `<html>` → slide keyframes in index.css. The chrome stays put while content slides because each bar has its OWN view-transition name (`.vt-pin-header` / `-topbar` / `-sidebar` / `-tabbar` — names must be unique per element, or the transition aborts).
- **View Transitions don't exist on pre-18 iOS Safari** — there, AppShell keys the Outlet wrapper by pathname and plays a `.page-in` rise (universal fallback, else navigation is INSTANT = "animations aren't there" on the primary device); with VT support the key stays constant (no double animation). That wrapper is `h-full` ONLY on routes flagged `fullHeight` in the registry (today only `/games`) — everywhere else it must stay auto-height or tall pages overflow the fixed box and swallow main's bottom padding (last card pinned under the tab bar; real regression, caught by E2E).
- **ALL view-transition CSS lives OUTSIDE `@layer`** — same Tailwind purge gotcha as the recharts rules; the original crossfade rule inside `@layer base` was silently purged from every build.
- `.stagger-in` (mobile-only ≤639px) cascades a container's children in with 30ms-stepped delays — HomePage, Daily's glance board and TasksPanel, Food, MediaPage.
- **BottomTabBar is a flat, full-width glass bar** (`h-tabbar` = `--app-tabbar-h` 64px + safe area; active tab = `text-accent-600` icon + label, no chip) — on phones `<main>` reserves `pb-[calc(var(--app-tabbar-h)+env(safe-area-inset-bottom)+16px)]`. `MoreSheet` lists the `more` pages (`moreFirst` entries — Wishes — on top), then Appearance/Accent/Display size/Notifications/Subscriptions/Sign out. `MobileHeader` hides on scroll-down, returns on any upward scroll and gains a shadow once scrolled (`chromeHidden`/`chromeScrolled` in `useUIStore`).
- **`.glass-chrome`** (index.css, `@layer components` — safe there because the class name appears in source, unlike runtime-only selectors) gives the phone header + tab bar their glass: `cream-50/0.82` + `backdrop-filter: blur(18px) saturate(160%)`, with an `@supports not` near-opaque (0.97) fallback. **Write only the standard `backdrop-filter`** — autoprefixer emits the `-webkit-` Safari needs; hand-writing both made the minifier drop the standard one. The glass frosts because `<main>` scrolls BEHIND the chrome.
- **iOS input auto-zoom is disabled app-wide** (real bug: tapping the AI chat box zoomed the page and the zoom stuck after blur, misaligning the frame — iOS zooms whenever a focused text control's font-size is <16px): `maximum-scale=1` in the viewport meta (pinch-zoom still works — iOS ignores max-scale for pinch since iOS 10) + a `@media (pointer: coarse)` rule forcing all text-entry controls to `font-size: 16px !important`. This removes the trigger itself — never "fix" this per-field.
- Touch polish: `-webkit-tap-highlight-color: transparent` + `touch-action: manipulation`, press-scale on buttons/interactive cards, `animate-tabPop` on the active tab.
- iOS PWA is edge-to-edge (`black-translucent` status bar + safe-area top padding on the header); `theme-color` matches the canvas (`#F3F5F9` light / `#06090F` dark). Pages sizing to the viewport use `min-h-full` — never `min-h-[calc(100vh-56px)]`.
- **Back closes only the top overlay** (`useHistoryDismiss`, built into `ModalShell`/`SideDrawer` and used by the Games page's sheets and the Media popup's title steps): open overlays form a stack, only the top one reacts to a Back (a Forward never closes one), and an overlay closed by other means drops its own history entry with a Back that nothing else treats as a Back. (Before, closing a sheet over a ScreenScraper review also closed the review, and opening a sheet while another overlay unmounted could close the new one.) **Entries left behind are passed over** (08.10.2026): a link inside a popup buries the popup's entries under the new page (the route change closes the popup), and a reload forgets every overlay. Each overlay entry carries the page's router state, the next `idx` and a page-load mark, so the module's popstate listener (registered before the router's) recognises an entry no open overlay owns, keeps that landing from the router and hops on in the direction of travel — one Back from the new page returns to the page the popup was on, one Forward returns to the new page; a Forward with nothing beyond rests there, and the next Back (like the first Back after a reload with a popup open) also skips the unchanged page beneath. Pure decisions in `historyEntries.ts` (`scripts/verify-history-dead-entries.cjs`, 104); AppShell reports the router's own pushes/replaces (`noteRouterNavigation`). **A popup that is saving holds** (28.10.2026): while `ModalShell`'s `dismissible` is false a Back leaves it open and pushes its entry again, kept from the router, and its sheet doesn't drag — before, the Back spent the popup's entry, so after a failed save the next Back left the page and the form was lost. Before, Back needed an extra press and the new page got `idx: NaN`. Not yet confirmed on an iPhone edge swipe (a 600 ms timeout covers a missing popstate).
- **iOS standalone short-viewport bug (reported: the tab bar floated ~a status bar above the screen bottom on every page):** in the installed PWA the layout viewport can be short by the top safe area, so `100dvh` and `fixed bottom-0` stop early. `app/iosViewportFix.ts` (standalone only) sets `--ios-viewport-gap` = screen height − the height a `position: fixed; inset: 0` probe actually covers (0–80px, else 0; re-measured on resize, return from background and `pageshow`). `innerHeight` was tried first and is wrong: it can stay short while fixed layout is already full height, which pushed the bar below the screen; `#root` adds it to its height and the phone tab bar (`BottomTabBar`) sits at `bottom: calc(-1 * gap)`. A no-op in the browser. Not yet confirmed on a device.
- **Never `overflow-x: hidden` on html/body** (real regression, 07.10.2026): it makes body a scroll container (the other axis computes to auto) and in the installed iOS app the tab bar and every bottom sheet floated a status bar above the screen bottom. The sideways-pan guard is `<main>`'s `overflow-x-hidden` (AppShell) plus `#root { overflow-x: clip }` (clip makes no scroll container).
- **CommandBar (⌘K) has a phone trigger**: `MobileHeader`'s Search icon button (⌘K can't be typed on a phone).
- **Motion test set** (THEME §7): card lift, count-ups, ring sweeps, check pop, row arrival and toast fade — always on (the Animations setting was removed 29.09.2026), never with reduced motion (a global reduced-motion rule also stops the base slides; JS motion checks `useMotion()`).

**iOS platform limits — hard constraints for anything "while the app is closed"** (full rationale: `docs/iphone-web-integration.md`):
- **No background execution at all.** PWAs get no Background/Periodic Sync; Shortcuts has no daemon. Unattended runs need a trigger (time/location/NFC) and **iOS forces a visible banner on every auto-run automation**. Server→phone delivery must go through Web Push.
- **iOS Web Push:** home-screen-**installed PWA only** (never a Safari tab), iOS 16.4+, direct-tap permission grant, and **every push must display a visible notification** (no silent data push). Delivery is best-effort and may be minutes late.
- **Web Share Target is unsupported on iOS** — "share a photo into the app to log it" would need a native Share Extension (a real App Store app).
- **Scriptable widgets:** refresh budget ≈40–70/day, ≥5 min apart, iOS decides the real cadence; a **Small widget has ONE tap target** and cannot run code in place — a tap opens a deep link (the `HizliLog` runner pattern).

## Routes

```
/#/login          → LoginPage (public)
/#/reset-password → ResetPasswordPage (public — reachable only via Supabase's recovery email link or LoginPage's "Forgot password?")
/#/home       → HomePage
/#/daily      → DailyPage    (nav: "Personal" — Daily ONLY, no in-header group tabs)
/#/recipes    → RecipesPage  (nav: "Food")
/#/shop       → ShopPage     (nav: "Shop" — its own entry since 06.10.2026: sidebar under Life, phone More sheet)
/#/media      → MediaPage
/#/work       → WorkPage
/#/projects   → ProjectsPage
/#/training   → TrainingPage
/#/health     → HealthPage   (Apple Health; a Training tab until 27.09.2026)
/#/games      → TestGamePage (inside AppShell, fullHeight; ?section=&platform= in the address)
/#/games-legacy → redirects to /#/games (the old Games page was deleted 26.09.2026; /#/games-demo and /#/games-cover-demo redirect too)
/#/wishes     → WishesPage   (reached from the phone More sheet — the 5 tab-bar slots are full — and the sidebar)
/#/books      → BooksPage    (More sheet + sidebar; ?tab=library|reading|send)
/#/developer  → DeveloperPage (sidebar footer, More sheet, Settings ⚙ menu)
/#/settings   → SettingsPage  (avatar menu, More sheet, sidebar footer; tabs Places · Appearance · Subscriptions · Integrations and APIs; old `?tab=integrations` opens Subscriptions)
/#/test-game  → redirects to /#/games (its name while under test)
```

Everything except `/login` and `/reset-password` is protected by `SessionGuard` in `src/app/router.tsx`.

**Nav grouping** (all in `src/app/navigation.ts`; routes are stable so deep links never break): sidebar groups **Overview** (Home) · **Life** (Personal, Food, Shop, Training, Health, Wishes) · **Media & play** (Media, Games) · **Work** (Work, Projects), Developer in the sidebar footer. Phone tab bar = 5 slots (Home · Personal · **Food** · Media · Training) + More; **Wishes leads the More sheet** (`moreFirst`), Health follows it (a wish list that has to be hunted for is dead in three weeks). Shop is its own entry (sidebar + More sheet, owner 06.10.2026); the old Food | Shop switch is gone. Daily renders no group tabs.

**Password reset (real bug, fixed):** the app had no recovery flow — Supabase's reset email redirected back with a recovery token, but nothing read it or showed a "set new password" form, so the link silently did nothing (a very common gap — see the `gotrue-js`/`auth-js` issues about apps not handling `PASSWORD_RECOVERY`). Fixed: LoginPage's "Forgot password?" → `requestPasswordReset()` (`security/supabaseClient.ts`) calls `supabase.auth.resetPasswordForEmail(email, { redirectTo })` pointing at `#/reset-password`; `ResetPasswordPage` listens for the `PASSWORD_RECOVERY` auth event (plus a session-check fallback in case the event fires before the listener attaches). **One-time manual step:** the redirect URLs (`https://lasciviens.github.io/Project_Daily/#/reset-password` and `http://localhost:5173/Project_Daily/#/reset-password` — the app sends `origin + BASE_URL + #/reset-password`) must be added to Supabase Dashboard → Authentication → URL Configuration → Redirect URLs, or Supabase silently refuses to send the token.

## Dark mode

Light/Dark/System (+ accent swatches) in `SettingsMenu.tsx` and the phone More sheet → `useThemeStore` (Zustand + persist, key `theme-preference`; `version: 1` moved the accent in from its own `accent-theme` key and reset everyone to the **blue** default once). `tailwind.config.js` (`darkMode: 'selector'`) resolves every token (semantic `surface`/`fg`/`line`/tones plus the legacy `canvas`/`cream`/`ink` aliases) through `rgb(var(--x) / <alpha-value>)`; `index.css` defines cool slate light values (`:root`) and dark overrides (`:root.dark`) once, so token classes are theme-aware with zero per-file branching. The accent's light/dark scales are inline vars on `<html>` (`applyAccent`, re-applied after every `.dark` toggle). An inline script in `index.html` stamps `.dark` synchronously from the persisted value (no flash-of-wrong-theme); a `matchMedia` listener keeps `'system'` live. Charts read `useChartColors()` (SVG can't read CSS vars); **identity colours** (sleep stages, Strava orange, transit lines, Activity Rings) stay fixed literals. Details: `docs/design/THEME.md` §2. `version: 3` dropped the old `motion` field (Animations setting removed; the motion set is always on).
