# Prisjakt and store product pages (schema.org)

Checked: 10.11.2026 — every page named here was read that day, once, with a generic client name (not the app's own): Prisjakt's robots.txt and terms of use; six live product pages, each run through the real `priceRead.ts` — Prisjakt "Kärcher Puzzi 8/1" (`p=11802129`), "Apple iPhone 15 128GB" (`p=12105524`) and "Apple iPhone 15 Pro 128GB" (`p=12105530`, kept trimmed as `scripts/fixtures/prisjakt/iphone-15-pro-128gb.html`), Elkjøp's TCL MQLED75K 65-inch TV (`899848`), Power "Kärcher SE 3 Compact Home" (`p-4229993`) and Jernia "Møbel- og tepperenser SE 3 Compact" (`12310223`); the robots.txt of Prisjakt, Elkjøp, Power, Jernia and FINN (kept as `scripts/fixtures/robots/`); the terms of finn.no and tise.com. The shapes were first checked live on 08.10.2026; trimmed copies of those pages are the fixtures in `scripts/verify-shop-price-read.cjs`.

Shop's price watch reads the price behind a product link: Prisjakt's lowest price for a new one, its highest and how many shops sell it new, and beside them the cheapest used and refurbished offers — or a store's own price, its struck-out "before" price and its return window. **Neither is an API.** Prisjakt has no public one; we read the schema.org data in the page: a JSON-LD block (structured data in a `<script type="application/ld+json">` tag) that stores and Prisjakt publish for search engines. Best effort: a changed page or a block stops it, and the card then says why. Code: `supabase/functions/shop-price/index.ts` (fetching, the daily sweep) and the parser `src/features/shop/priceRead.ts` (hand-mirrored into the function, `verify-shop-price-read`). How the feature works: `docs/features/shop.md`; its rules: `.claude/rules/shop.md`.

## How we authenticate

- **Nothing to sign in to**: public pages, no account, key or cookie.
- **Who can make `shop-price` read a page**: a browser JWT, checked with `auth.getUser` and then `isAppUser`; or the daily cron's `x-cron-secret` = `SHOP_PRICE_CRON_SECRET` (Edge Function secret and Vault, compared in constant time; acts as `HEVY_USER_ID`; `sweep` only). JWT verification is off for `shop-price` in `supabase/config.toml` (the cron sends none).
- **An honest User-Agent** (the line a program sends to say what it is): `Mozilla/5.0 (compatible; LascisBoard/1.0; +https://lasciviens.github.io/Project_Daily)` — it says it is an automatic reader and names the app; never a browser's line. With it: `Accept: text/html,application/xhtml+xml;q=0.9,*/*;q=0.5` and `Accept-Language: nb-NO,nb;q=0.9,en;q=0.8,tr;q=0.7`.
- **Fetch safety** (the same guard as `news-article`, `verify-ssrf-guard`): http and https only, no user name in the link, private hosts and names that resolve to a private address refused on every redirect (at most 5, followed by hand), 8 s for the whole read, 3 MB, HTML only. On every hop too, before anything is asked of the host: a site in `shop_site_policies` is refused, a path + query over 2 048 characters (`MAX_PATH_CHARS`, as long as a kept link) is not read now (status `error`, "The link is too long to read"), and the page's own robots.txt must allow its path (below).

## What the sites allow, and our limits

### Prisjakt's robots.txt

robots.txt is the file in which a site says what automatic readers may fetch. https://www.prisjakt.no/robots.txt, for every reader (`User-agent: *`):
- **Product pages are allowed**: `/product.php?p=<id>` (and `/produkt.php`), with a variant such as `&a-116257=Frost` too. Only `/product.php?o=*&offset=*` and `/product.php?e=*&edit=*` are disallowed.
- **Search is disallowed** (`Disallow: /search?*`), and so are `/redirect.php`, `/go-to-shop`, the price lists (`/prisliste/` …), `/account/*`, `/login` and some category filters (`/c/*?*sort=*` …).
- It sets no crawl delay; ours is below.
- **The code keeps to it, and to every other site's** (since 10.11.2026, `robotsRules` / `robotsAllows` in `priceRead.ts`, RFC 9309 — the standard for robots.txt): before every page request — `read`, `check`, the sweep and each redirect hop's new host — `shop-price` reads that page's own `<scheme>://<host>/robots.txt` through the same fetch guard (4 s, 512 KiB, redirects re-checked, at most 5), keeps the rules in memory per origin for 24 h, and takes the group for our product token `LascisBoard` (the name in the User-Agent; no site names it today), else `*`. Patterns with `*` and a final `$`, matched against the path and the query; the longest match decides and Allow wins a tie. Both sides are put in one form first (RFC 9309 §2.2.2; the guardian review, 10.11.2026): an encoded unreserved character is the character, so `/%73earch?x` meets `Disallow: /search?*` (before, it passed, and so did `/%70rivate` and `/%7Estaff`); every other `%XX` keeps its hex in capitals (`%2F` stays `%2F`); and spaces, controls, non-ASCII and the characters the URL parser encodes — `"` `'` `<` `>` `` ` `` `{` `}` — are percent-encoded, so a rule's raw `{x}` meets the link's `%7Bx%7D` (before, it never matched). More than 5 000 rules for us (`ROBOTS_RULE_CAP`) is a file that can't be read: not read now ("The site's rules for apps are too long to read", `error`) — before, the rules past 5 000 were dropped silently. A disallowed path is never fetched: status `not_allowed`, "prisjakt.no asks apps not to read this page" (the add sheet adds "— paste the product's own page"). A 4xx (404 included) means no rules; a 5xx, a network error or no answer in time means "not read now" (status `error`, remembered 10 minutes), said as a page that failed is — "The site answered with an error (503)", "The site didn't answer" — and the next morning's sweep tries again.

### Prisjakt's terms

https://www.prisjakt.no/info/regler-og-retningslinjer-for-brukere--i4 now redirects (`301`) to https://www.prisjakt.no/information/brukervilkar — one page, updated 26.10.2026, in force since 10.06.2025:
- **Automated collection is not allowed, apart from crawling within robots.txt** (unless mandatory law or a separate written agreement with Prisjakt says otherwise): «… er det ikke tillatt å bruke automatisert teknologi (som gjennomgang, skraping og indeksering, for eksempel til tekst- og datautvinningsformål) for å samle inn data fra Tjenestene …» and «Prisjakt gir begrensede tillatelser til å gjennomsøke Tjenestene i samsvar med parameterne spesifisert i Tjenestenes robot.txt-filer.»
- **Only within normal use**: the material and information «kan ikke brukes på annen måte enn innenfor rammen av normal bruk av Tjenestene». Access «er kun beregnet for personlig bruk», and nobody may put «en urimelig eller uforholdsmessig byrde» (an unreasonable or disproportionate load, in Prisjakt's judgment) on the service or spread its material to the public.
- **What we do with that**: product pages only, which robots.txt allows; one person's private list (row-level security lets only the owner read the watch); nothing published; a few pages a day, spaced out.

### The owner's limit (10.11.2026)

**Each product page at most once a day, and only for things being watched or still returnable.** What the code does (since 10.11.2026):
- **The morning sweep** (pg_cron `lascis-shop-prices`, 05:23 UTC daily) reads only things to buy (`status 'wishlist'`; a model only while its general wish is open) and things owned that can still go back (`status 'bought'`, not gone, `return_by` today or later in Oslo) — each only when its last check is more than 20 hours old (or it was never checked, or its link changed), oldest first, at most 40 a run, stopping after 100 s (the rest wait for the next morning). One run a day, so the sweep reads a page at most once a day.
- **What the owner starts reads a page at most once an hour**: `read` when a link is pasted or Read is tapped (a preview, nothing stored), the quiet `check` right after a row with a link is saved, and **Check now** (up to 10 rows). `check` doesn't fetch a row whose watch has the same link and was checked under an hour ago — that check is the answer, and the toast says "Already checked at 14:05 — try after 15:05" (a bot check or no price: a warning in its own words, "Already checked at 14:05 — elkjop.no blocks apps with a browser check"). A refusal is answered as itself, and a failed check (`error`) read nothing, so Check now tries it again at once; a refused link has no Check now in the record. `read` and `check` also share the last hour's reads in memory, by account and exact link, so pasting a link and saving it is one read (the preview says "read at 14:05" when it reuses one). The memory belongs to one function instance: a request served by another one may read once more.
- **What said no isn't asked every morning**: the sweep never asks again a link whose last answer was a refusal (`not_allowed`) while the link is unchanged, and asks one whose last answer was a bot check (`blocked`) again on the 7th Oslo day after that check (`BLOCKED_RETRY_DAYS`, the same in `watchWords.ts`) — a bot check may be lifted, and one for good would otherwise stop that link's morning check for good without a word. The card and the record say the day: "the morning check tries again on 17.11.2026". Check now still tries (once an hour); a failed check (`error`) is tried again the next morning.
- **1.5 s between two requests to one host** (`HOST_GAP_MS` in `politeRead`). The time of the last request is remembered per function instance: two calls served at the same moment by two instances are not spaced. The sweep is one call, so its requests are.

## Fields we deliberately don't use

- `aggregateRating`, `review`, `additionalProperty` (Prisjakt's specs), `BreadcrumbList`, `Organization`: nothing on screen uses them.
- `brand` and the EAN: read and answered by `read`, never stored — the row keeps the title the owner gives it, and a grocery's EAN comes from Kassalapp (`docs/integrations/kassalapp.md`).
- `itemCondition` on a store's offer (Elkjøp, Power and Jernia: `NewCondition`) — a store's price is stored as `condition = 'unknown'` — `sku`, `mpn`, `seller`, `shippingDetails`, `availabilityStarts` (Power's is "27.11.2026 00:00:00", not ISO), `hasEnergyConsumptionDetails`, `hasCertification`.
- Prices for some customers only: an offer whose `eligibleCustomerType` isn't Public (Elkjøp's business price without VAT) is skipped while a public one exists; a return policy with `validForMemberTier` is skipped; Jernia's `priceSpecification` (1990 for club members, beside the public 2490) is never taken for the price.
- In Prisjakt's offer rows: `stockStatus` (the price now stays the cheapest new offer, in stock or not, as the schema.org figures were), `conditionGrade`, `priceType`, `originalPrice`, the listing's `name`, the shop's name, logo and reviews, `shipping`, `clickoutUrl` (never followed), `isFeatured`, `promotion`, `deal`. The colour picker's `lowestPrice` (scaled by 100, and mixed like the AggregateOffer). The headline "fra 16 115 kr" and the description's "Laveste pris" (text, and the same as the new offers' low).

## Traps

- **AggregateOffer mixes new, refurbished and used offers — so the price now comes from the offer list.** Live 10.11.2026, "Apple iPhone 15 128GB" (`p=12105524`): Prisjakt's own headline says "fra 7 504 kr" (new), but the Pink variant's JSON-LD says `lowPrice: 4990`, and in the page's own offer list that is a used offer ("Apple iPhone 15 - Brukt / 128 / Pink", `"condition":"Used"`); Green 5444 is used too, Yellow 5790 refurbished, Black 7504 new. "Apple iPhone 15 Pro 128GB" (`p=12105530`): the JSON-LD's cheapest variant read 6 590, a refurbished offer; its only new offers were 16 115 and 16 252. **Fixed on 10.11.2026** (Shop phase 1, migration 188): the price now is the new rows of the offer list, and a card whose low was a used or refurbished price now shows the (higher) new one — or none, when only used ones are left: a check whose list has no new offer drops a kept price of another kind (read before 188, or mixed) with its high, shops, "was", trend and day, keeps the name, the picture and the used and refurbished lows, and the card says "No new offer on Prisjakt" (a kept new price stays as the last new price read). Still mixed: a link to one colour on a page that lists every colour (rows don't say their colour — the colour's schema.org figures are read, marked `mixed`), and a page without the list; the screens say so ("lowest at Prisjakt, new and used", the card's "on Prisjakt, new and used"), and a Prisjakt price from before 188 (no condition) is said the same way. Points read before 188 have no condition (NULL): the record's history draws and sums up only the points of the watch's own kind (`watchWords.historyOf`; a NULL Prisjakt point counts as mixed), so its "lowest" never sets a refurbished 6 590 against a new 16 115, and a line names the ones left out ("Left out: 4 prices that mixed in used offers").
- **A review could fake the offer list** (the guardian review, 10.11.2026): React sends a string of 1 024 characters or more as a raw text row (`<id>:T<hex bytes>,<text>`) with no JSON escaping, so a long user review holding `"offerRows":[…99 NOK…]` was read as the page's list (the first `"offerRows":` anywhere) and stored 99 as a new price. Now the stream is read row by row and a row sent by length is stepped over by its byte count (UTF-8: "ø" is two bytes, an emoji four); a short review sits inside a JSON row, escaped, so it never was a list; and a list counts only when it is the only one holding this product's offers — none (an empty list too) or two, and the price is the schema.org figures, marked `mixed` ("new and used" on screen). A stream that stops being rows is read up to there.
- **The offer list is the page's own React data, not a published format.** It sits in `self.__next_f.push([1,"…"])` scripts that Next.js (the framework the page is built with) streams; a rebuild can rename or move it. Then the reader falls back to the schema.org figures, marked `mixed` — the card's price may then be a used one again; the stored condition says so, and the card, the strip and the record show it as "new and used". `verify-shop-price-read` runs the trimmed live page; a new sample shows whether it still holds.
- **A bot check is `blocked`, never a price.** Some sites answer an automatic reader with a check page instead of the product: Cloudflare's (a service in front of many sites) "Just a moment…" or "Attention Required!" (Prisjakt's search, Proshop), a "Client Challenge" (Clas Ohlson, 08.10.2026), or a page carrying `window._cf_chl_opt` / `cf-browser-verification` (`isChallengePage`). Such a page is `blocked` even when it comes with a 403 or 503. Cloudflare's `challenge-platform` script is on every Prisjakt page, real ones too, so it proves nothing. A blocked check keeps the last price and says "elkjop.no blocks apps with a browser check" (the site's name, without "www.").
- **robots.txt is checked for every site, on every hop, since 10.11.2026** (above): a pasted `prisjakt.no/search?…` link is `not_allowed`, never fetched. Before, it was not checked at all (`isPrisjaktUrl` existed, unused). The rules are remembered per function instance for 24 h: a site that tightens its robots.txt is obeyed within a day. A robots.txt that can't be read stops the read ("not read now"), never counts as "allowed".
- **A refused link is not asked again by the sweep, a blocked one once a week** (since 10.11.2026): before, the sweep's due rule looked only at when a link was last checked, so a bot check was requested again every morning; the first fix skipped a blocked link for good, which stopped its morning check after one bot check with nothing on screen saying so. A failed check (`error`) is still tried the next morning.
- **The one-hour memory is per function instance.** Paste then save within seconds is one read when one instance serves both (the usual case), two when two do; the watch's own `checked_at` (an hour) is the rule that always holds for Check now.
- **Prices come as text or as numbers**, in Norwegian forms too: `parsePrice` reads "9 990,00", "kr 1.299,-" and "1,299.50", and takes "9.990" for nine thousand nine hundred and ninety.
- **A hostile page or robots.txt must cost a moment, never the sweep** (the guardian review, 10.11.2026: the worker died, and in the sweep the poisoned item sorts first every morning): a price text over 64 characters is no price before any pattern runs on it (80 000 dashes took 4.9 s); the JSON-LD blocks are found in one pass with `indexOf`, stopping at the first script tag that never closes (256 KiB of unclosed "<script " took 6.4 s); a robots pattern is matched piece by piece between its `*`s, leftmost first (5 000 rules "*aaa…ab" took 9.3 s on a 2 000-character path, now about 50 ms); and no path + query over 2 048 characters is matched or read. `verify-shop-price-read` times each with the hostile input.
- **Elkjøp's first price specification is the price without VAT** (`11999.2`, beside the offer's `"14999"`): the offer's own `price` is read first, so it would only count for an offer with no `price`.
- **`@id` links are not followed.** Jernia's offer names its return policy only by `@id`; the page defines that policy on its Organization with a `merchantReturnLink` and no number of days — so a Jernia link never has `return_days`.
- **Elkjøp's EAN field changed name**: `gtin` on 10.11.2026, `gtin13` in the 08.10.2026 fixture; both are read.
- **The source label is a text match** (`/prisjakt\.no/` on the final URL): a store link that mentions prisjakt.no in its query would be labelled Prisjakt.
- A page without a price still gives its name and picture (`no_price`; the last price stays). A link changed while it was being read saves nothing ("The link changed while it was checked"). A second read within the hour with the same numbers adds no history point.
