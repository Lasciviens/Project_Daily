# Shop rules

Background: `docs/features/shop.md`.

- Every purchase, sale and cost is NOK at the rate of its own day, frozen on the row by the database; a missing rate is "rate pending", never today's rate. Today's rates only for values of now.
- A possession is `list='wishlist' AND kind='item' AND status='bought'` and kept (`ownModel.isPossession`); quick-list ticks never are.
- Selling never deletes: it writes the disposal facts (one `shop_record_sale` call, Undo `shop_undo_sale`); accessories sold together share a `sale_group`.
- Deleting a shop item takes the accessories bought for it (`shopModel.deleteScope`), the same from every screen.
- `shop_price_watch`/`shop_price_points` are written only by `shop-price` (Delete's Undo puts them back through `shop_restore_price_history`, 187), never `shop_items`.
- `priceRead.ts`, `productFacts.ts` and `fxNorgesBank.ts` are hand-mirrored into `shop-price` (their verify scripts compare them). `productFacts.ts` is its own module so the add sheet's facts never ride into the Shop page's first chunk (priceRead's parsePrice sits there).
- Never read a site whose terms forbid automated reading: the list is data — `shop_site_policies` (188), a host or its subdomains — never a store name in code (owner, 10.11.2026). `shop-price` checks it before every fetch and every redirect hop, in `read`, `check` and the sweep, and fails closed when it can't read it (every row, page by page — a list cut at 1 000 would read a listed site); the answer is `not_allowed`, shown in plain words ("finn.no doesn't let apps read its pages").
- Read a page only where its site's robots.txt allows it — every site, every request (`read`, `check`, the sweep, each redirect hop), through the page fetch's own guards; never a site name in code. A disallowed path is `not_allowed` in its own wording ("prisjakt.no asks apps not to read this page", never the terms' wording); a robots.txt that can't be read means "not read now" (`error`), never "allowed"; a 4xx means no rules (RFC 9309). The rule and the link are compared in one form (an encoded unreserved character decoded, the characters the URL parser encodes encoded, hex in capitals), and more than `ROBOTS_RULE_CAP` rules is "not read now" — never rules dropped past a cap.
- One vocabulary for what a site refuses or fails, on every screen (owner, 10.11.2026): "apps" — never "robots rules" or "automated reading" — and never "open it yourself" right after the owner pasted the link. `shop-price` writes the site's answer (the watch's `error`, the read's `reason`); `watchWords.ts` adds what to do, the same for the add sheet and Add a model.
- Page text is kept as Delete's Undo keeps it (`keptText` in `priceRead.ts`): a name ≤ 300 characters, a picture only a web link ≤ 2 048, a currency only `^[A-Z]{3}$`; Prisjakt is told by its host, never by a text match on the link.
- A hostile page or robots.txt costs a moment, never the sweep (guardian review, 10.11.2026): every page text is bounded before a pattern runs on it (a price ≤ 64 characters, a path + query ≤ 2 048), the JSON-LD scan is one pass, robots patterns match piece by piece (no backtracking); `verify-shop-price-read` times each with the hostile input — keep those bounds when the reader changes.
- Each page is read at most once a day (the sweep, 20 h) and at most once an hour for what the owner starts: paste, save and Check now reuse the last hour's read (a watch of the same link, or the in-memory read by account and exact link) and say so — never a failed check (`error`: it read nothing, so it is tried again at once); a refused link has no Check now; a site's answer without a price is a warning toast, never a green "checked" — never a second fetch to "refresh". The sweep never asks again a link whose last answer was `not_allowed` while it is unchanged, and asks a `blocked` one again on the 7th Oslo day after (`BLOCKED_RETRY_DAYS` in `shop-price` and `watchWords.ts`, compared by `verify-shop-price-read`) — the card and the record say that day (Check now still may); don't list a store in `shop_site_policies` only because it blocks bots — that list is for terms that forbid reading.
- Prisjakt's price now is its new offers only (its own offer list; its schema.org figures mix in refurbished and used ones) — read from the stream's JSON rows only, never a raw text row (`<id>:T…`, which a user's review fills), and only when exactly one list holds this product's offers; otherwise its schema.org figures, marked mixed. Every watch and point says what its price covers (`condition`: new, mixed, unknown; NULL = before 188) — a later "lowest seen" compares like with like and leaves NULL Prisjakt points out (the record's history: `watchWords.historyOf`, a NULL Prisjakt point counts as mixed, and the ones left out are named); a price of another kind starts its own trend. When the offer list has no new offer, a kept price of another kind (NULL or mixed) goes — it is never left on screen as the price now — and the screens say "No new offer on Prisjakt", not "Couldn't check". `used_low` / `refurbished_low` are offers seen, never a "Could sell for". A Prisjakt price that may be a used one (mixed, or NULL) says so on every screen (", new and used"); a refusal and a page without a price are answers, shown in a neutral tone with the kept price's day — only a bot check or a failed check is the warning tone (`watchWords.ts`).
- Needs a look remembers a row only through `shop_signal_snooze` / `shop_signal_dismiss` / `shop_signal_put` (190): each answers the row before and after, and Undo writes `before` back exactly — never when `before` was a row the app can't read back (`beforeUnknown`: no Undo, read the list again; an Undo would delete it); a Got it's `signature` comes from `signalStates.signalSignature` and is data, only compared — never shown or followed. One row per thing, signal and `subject` (a deal day's slug: each deal day its own), unique with NULLS NOT DISTINCT — never a stand-in id.
- A category and a thing's category are the account's own (190's `shop_categories_rules`, `shop_items_rules` step g): a foreign key ignores row level security. The Undo of a category just made passes its `created_at` and refuses before any write when a subcategory under it is older (the cascade would take it). Price figures for many things are one `shop_price_stats` call (`usePriceStats`), never one history read per wish, and count clean prices only (`new`, `unknown`). Deal days are rows (`shop_deal_days`) worked out by `dealDays.ts` — never a date in code.
- A tile's belt and bar and Needs a look's price rows count clean prices only (`wishTile.isClean`: a new offer's or a shop's own page — never a mixed Prisjakt figure or a pre-188 read), so a used price never looks like a deal; a refused link shows no price from the link and the site's own words, neutral (`watchWords.watchNote`: "finn.no doesn't let apps read its pages"), a bot check when the morning check tries again — the same vocabulary as the record and the add sheet.
- A done shop plan of a wishlist thing buys it as a draft (211, the database: `bought_at` = the tick, nothing else filled in) and leaves a server notice that Needs a look shows (`noticeLooks`: Open → the record's purchase, Got it reads it, never snoozed); unticking removes the draft only while unchanged. A return / complaint / handover plan only closes. Plan buttons go through `usePlanThis` (Return by / Complain by while that day is ahead, Handover in the sell sheet).
- Needs a look is one list for the whole Shop (`ShopNeedsALook`): one button in the Shop page's header on every view, a count badge laid over an icon so the bar never reshapes, opening the rows in a sheet (owner, 23.11.2026; before: the right rail on a wide page, one line on a phone — 14.10.2026 / 09.11.2026). A row's open action closes the sheet first; its thing opens in the record popup. On Owned it replaced Coming up, so a deadline is never listed twice — and it lists what Coming up did (returns from 14 days ahead). Every row has one action plus Snooze and Got it; a snooze never hides a deadline past its day (a week, or the day before it); a row Got it hid comes back only when its signature changes. Money to claim comes only from an `ok`, clean read; a price not read today says its day.
- Categories are suggested, and added only on the owner's tap — never seeded, never by a migration (owner, 10.11.2026): a picker (`CategoryPicker`) lists the owner's own first, then `shopTaxonomy`'s "Suggested" ones (Title Case, as 030's seed); a pick only picks it — the sheet's Save makes it (`useResolveCategory`), never the select's change (an iOS picker scroll), and its Undo says what moved and never touches a draft. **Add the suggested categories (N)** — the Shop header's ⋯ (while there are any) and the first line of a picker's Suggested group, which only asks in a line under the selects (the same iOS reason) — makes every suggestion once through `useAddSuggestedCategories` (`suggestedPlan` from a fresh read of the owner's own rows, so nothing is made twice); its Undo removes only the rows it made, and of those only the ones still empty and as made (`removeAddedCategories`, the same `created_at` guard), and names what it kept. Names match without case, spaces or "&"/"and", and through `aka` — the owner's own names win — so a suggestion never repeats what is there. A filter offers no suggestions (they hold nothing).
- A thing's picture: its own, its watch's, its subcategory's default, its top category's, else the initials. A default is a lucide icon on the category's tint, never a stock photo or an emoji; the icons and the taxonomy load in their own chunk (`useCategoryPictures`; `useAddSuggestedCategories` loads the taxonomy and its writes the same way), so the Shop page keeps its 400 kB budget.
- Each subcategory is named once, above its own rows or tiles (owner, 09.11.2026; approved with the tiles, 10.11.2026): a label over every card cost a line each.
- Every store and marketplace is a row (`shop_stores`, 191) with its rules (`shop_store_rules`) — never a store name, a day count or a law number in code (owner, 10.11.2026: "no power only processes"). A link's store is its host or a subdomain of one (`storeRules.storeOfLink`, the most specific wins); whether apps may read a store is 188's `shop_site_policies` by host (`storeSitePolicy`), never a copy on the store. A search link is the store's own pattern, https, on its own host, opened by the owner and never fetched (`searchLinkFor` checks it again).
- "You edited it — never overwrite" (owner, 10.11.2026): `owner_edited` is the database's, derived on every write from the row's facts against its `source_facts` — never sent by the app (an edit sends facts only; its Undo writes `before`'s facts back with its `edited_at`). A seed or a page read writes the source everywhere and the facts only where it is false; where it is true, show the source's words as a conflict (`sourceConflict`), never pick. A seeded rule is turned off and a seeded store hidden — the app never deletes one (the next seed would bring it back). The member tier and `hidden` are the owner's own, never facts.
- Seed only what has a source (its link and the day read); leave an unknown rule out, never guess. A store's rules come from its own page where the site lets apps read it — once, a generic client name, within robots.txt, never a site of `shop_site_policies` (owner, 11.11.2026); where it can't be read, a price site's words about the store are origin `price_site` ("from Prisjakt — check it", `storeRules.claimedBy`). What the assistant writes is `ask_ai` — "from Ask AI — check it". Both are `storeRules.unchecked`: on every screen with their source first, their label and tier never shown, never deciding a date on their own (a note; the date shown is unsure) and a price match from them is a caveat; a page read may replace them; the owner's edit wins. The app never makes a `price_site` rule and never deletes a seeded one; the assistant touches only its own. Free text on these rows is one plain line (`shop_plain_text_ok`: no control, zero-width or direction characters).
- Bought on a wish fills in how and where at once (`useBuyNow(…, { thenDetails: true })`): from a wish's tile and Needs a look it opens **Just bought**; inside a record it opens that record's Purchase in place (never a popup on top), and a model bought from its general wish saves the wish's draft first, then opens the model's record in the wish's place with its Purchase open. The quick list and Daily keep "Add details".
- A purchase's facts are 191's columns, written through `savePurchase` (the values before answered for Undo); before 191 a write of one — or of `facts` — says so by name (`NEEDS_191_ITEM`), never a retry that quietly leaves it out. `PurchaseFacts` comes from the row (`purchaseModel.factsOf`: `bought_channel`, `arrived_on`, the store's kind for the seller).
- Every outgoing link shows its address before it opens (THEME §12): "Look on FINN" a popover with the address and Open, "Find it" the whole address under each store, a rule's source its host with the whole link in its title, Needs a look's ↗ the offers page in its title. A search link is opened by the owner, never fetched, and only the day it was opened is kept (`search_opened_on`).
- A price protection nobody checked (Ask AI's, a price site's) decides nothing — no claim, amount, tone or "Claim by": `protectionOf` takes checked rules only; `protectionNoteOf` names one as an info note "… — check it" (security review, 11.11.2026). The Rule sheet says editing one makes it the owner's. The record's nudge offers Claim only where Needs a look's own row is a Claim (`nudgeFor`: `cheaper_returnable` with its `claim`), never a Claim of its own making (`verify-shop-purchase`).
- Every value of `shop_items.facts` has its key's shape (`shop_item_facts_ok`; `factsToSave` leaves out what doesn't fit). A link refuses zero-width and direction marks (`shop_https_ok`, `isShownLink`), `shownAddress` drops what decoding brings back, and a page's text loses them (`priceRead`). The price match row's ↗ is a price site's page only.
- Needs a look's store rows come from `storeLooks.ts` in its own chunk (`useStoreLooks`, the stores' module loaded on demand — never in the Shop page's first download): a price match for a wish, a price protection's Claim on the cheaper-than-you-paid row, every claim past the money already got back (`gotBackOf`). The list waits for them (`loading`) and a failed read of them is the list's Try again.
- The right to cancel is decided by the seller (`PurchaseFacts.seller`), never by the marketplace: a business on FINN gives 14 days, a private seller none.
- Price match reads `shop_price_watch.new_offers` (Prisjakt's new offers, one per shop, written by `shop-price` only) through `offersOfWatch` — a shop is found by its name or address, never by a guessed id.
- A deadline explains itself and names its source ("Return by 15.01.2027 — Elkjøp's Christmas returns, typed 10.11.2026"; `storeRules.purchaseDeadlines`): until Arrived is tapped it counts from the purchase day; two sources that disagree give the earlier date with both named (Power's 90 / 60); a rule whose exclusions aren't known isn't counted but named; the law's own last day (past a weekend or holiday, `norwayHolidays.ts`) goes in the words, the earlier date on screen. The law is Norway's only, from `shop_law_rules` — no right to cancel in a shop or from a private seller.
- Price match comes from the offer list already read (`priceMatches`): new offers in stock in the store's currency, only when cheaper than its own — never a used, refurbished or marketplace offer, never a second fetch — and says when it was read ("Elkjøp matches Power: 2 990 there, read 05:23").
- Deal days the owner edits are their own rows over 190's (`shop_deal_day_edits`, by slug; `effectiveDealDays`): 190's rows never change from the app, and Reset deletes the owner's version.
- Never invent a price, a sale price or a "Could sell for".
- Buy again comes from the owner's own quick-list ticks only (`buyAgainModel.ts`, pure, `verify-shop-quick`): three purchase days with gaps that agree (two gaps: the longer ≤ 1.5 × the shorter), a rhythm of 8 weeks at most, due from 80 % of the usual gap until one more gap (two weeks at most) has passed — never nag about things bought now and then, never while the thing is on the list by name or EAN — never a guess from outside data. One group leading the list, inside its box (it takes the skeleton's place — never a section that pushes a drawn list); a tap re-adds the latest purchase with "On the quick list · Milk · Undo", Undo takes that fresh row off (`useAddAgain`, shared with Bought before).
- A product's picture on a quick-list row is the row's own `image_url`: Kassalapp's `image` is saved only when the row has none (or exactly the old product's, on Change product) and only as a web link on a public host, made https, ≤ 2 048 — no user/password, IP, localhost, .local or single-label host (`webPicture`, the same in `food-search`) — no picture shows nothing, never a stock photo or placeholder.
- A scan asks `food-search`'s `grocery_ean` (`GET /products/ean/{ean}`), never the name search: the code only as 8–14 digits — the app (`scanEan`) and the function (`EAN_RE`, tested as sent, before the address is built) both refuse anything else; the function keeps `auth.getUser` + `isAppUser` first, and every field of the answer is checked where it enters (the `<grocery-ean>` block, `groceryHitOf`). Its shape is Kassalapp's own example, not a live sample — say so until one is seen.
- The basket card's subtitle answers where the whole list is cheapest (`wholeList`, `wholeListWords`): from the per-chain basket, so current prices only; it never calls a chain cheapest on rows it lacks, and says "for these" while rows are unpriced; the amounts stay on the chains' rows.
- A one-tap add to the quick list (Buy again, Bought before, a scan) names the row with Undo and ignores a second tap with the same key while it saves (`useQuickAddWithUndo`: a ref, never only `isPending`).
- The Quick list is its own chunk (`lazyPart` in `ShopPage`, preloaded in idle time) and the grocery hooks live in `useGrocery.ts`, so quick-only code never joins the Shop page's first download (400 kB budget).
- Autofill (`autofillModel.ts`, `factsKept.ts`, `components/autofill/`, lazy — keep it out of the Shop page's chunk): every fact says its source and a confidence word — exact (a data-block field, a valid barcode), likely (derived), check (a guess) — as a tone. Brand only from the data block (`brand.name`), never the title or the link; a model read from a name is "check"; an EAN is 13 digits with its check digit verified, else none (`ean13`). A form fact fills only an empty field or one still holding an earlier fact — never over what the owner typed — and is saved with its source only while its field holds it; the owner's edit (source "you") is never replaced by a read. A barcode asks the owner's own things first, then groceries — no outside source for durable goods (no Open Icecat, no Open Products Facts: the 10.11.2026 test). A title asks only the owner's own history.
- "Find it" links come from store rows' patterns (191's `search_url`, data), with `{q}` encoded, ≤ 150 characters, refused unless the result is an `https:` address without a user name on the store's own host (`searchLink`, then `storeRules.searchLinkFor`'s host check); each shows its whole address before it opens. "You may already have this" (EAN, Prisjakt product, folded title) never blocks Add.
- `shop_items.facts` (191) keeps autofill's facts with their sources: only 191's keys (brand, model, ean, condition, return_days, prisjakt_id, specs), each exactly `{value, source, confidence}`, the source one plain line ≤ 200, the whole ≤ 8 KiB (`shop_item_facts_ok`; `factsToSave` writes that shape and trims specs to fit) — a form fact (name, price, picture, store, category) is its column, never a fact. Read-only to the assistant (`AI_NO_WRITE`); Delete's Undo carries it; a chain's rows write it empty (`FullShopItem`).
- Resale (192): an ad's link (`ad_url`) is https only, then printable ASCII (one allow-list in the database and `resaleRows.AD_URL_RE`, checked on `scripts/fixtures/shop-ad-links.json`; the app sends `normalizeAdUrl`'s href), **never fetched** by anything and never written by the assistant — nor an ad's text or a marketplace (`AI_NO_WRITE`); a marketplace is a host (data), never a name in code (191's stores join it by host later). Sold is never written by hand: the sale (`shop_record_sale`) closes the thing's open listing and its Undo opens it again (`shop_items_resale`), and a listing's thing is checked when the transaction ends (Activity's Undo puts rows back newest first). A listing's price story is its own `prices` (a table pointing at a listing would be lost by Delete's Undo). The value history is the database's (every "Could sell for" with its day): a change takes back only the previous estimate's own row, never other days'. Text bounds count every character and need a non-space (`char_length(x) <= N and x ~ '\S'`, never `btrim`); amounts are below a billion. `resaleEvidence` counts only fresh rows with a NOK amount, never your own estimates or a "for parts" ad, and fills nothing in; ad templates are Norwegian, checklists English — both the owner's rows, read only for the assistant.
- Selling (step C screens): the suggested range only suggests — Use writes the record's draft, Save keeps it; nothing fills itself in. An ad's link and a marketplace's front page are links out that show their address and are never fetched (`AddressLink`: only `isAdUrl`, no referrer, the host in full and only the path cut — a long look-alike host never hides the real one); a marketplace link is built from its host only and only for a host the owner's templates name (`marketplaceLink(host, marketplacesOf(templates))`) — a listing's marketplace is input the assistant could have written, shown as text (security review, 11.11.2026). The ad is copied to the clipboard and never posted anywhere; its facts are the name, the condition, the day bought, the asking price (the listing's, else the owner's own estimate) and the accessories ticked — never a serial, the store, what it cost or a buyer. Sold is only the sell flow (`shop-sell`): a listing screen never writes Sold. A price cut is typed or a share of the owner's own price (`priceCuts`), never a price from outside.
- Hand-over ticks are a device note (owner, 11.11.2026; `lasci.shop.handover`, the last 20 things, by the step's words, cleared at sign-out): the database keeps the steps, the owner's rows; a step edit saves with Undo. New selling parts load in their own chunks (`lazyPart`) inside the record, never in the Shop page's first download.
- A Kassalapp price counts (Cheapest now, a row's chip, the baskets) only when checked today or on one of the 14 Oslo days before — no date, no trust (`groceryModel.isCurrent`, every price through `byChain`) — and the basket says how many it left out and why ("4 old prices left out — not checked in 14 days", the chains on a tap): REMA 1000, Kiwi and Coop still come back with prices from 2024 (Kassalapp's FAQ, 10.11.2026).
- Money back from a claim or a price match is a rebate on the thing — a negative extra cost (`shop_item_costs`), never a new money path — labelled by `complaintModel.REBATE_LABEL` (Stats counts it as saved through `rebateKind`), and its toast offers Undo (`useMoneyBack`, its own file so the Shop page's first download never carries it). The complaint letter is Norwegian content built from the thing's facts only (`complaintLetter`); every fact in the letter and the ad goes through the one `oneLine` (no line breaks, control characters or bidi controls; the zero-width joiner stays) — a title may be the assistant's, so both are on screen and editable before Copy, never sent by the app. The store's page shows only for an https link that is not a price site's (`storePageOf`); the complaint right is the noted day, else the law's two years from the purchase day — the earlier day when unsure. Something's wrong saves only the money back (owner, 11.11.2026): what's wrong and the letter stay on the screen, copied by hand.
- New vs used vs refurbished (a wish's record, `RecordOwnership`; shown whenever `worthShowing`, with a link or without) compares only prices the Shop has (`ownershipPrices`): new from a clean read of the wish's own link, else its own price; used and refurbished only Prisjakt's offers on that read, in the same currency — offers to buy, never a "Could sell for". A net cost comes only from your own kept % (`ownershipCost`: your sales and trade-ins at each day's rate), never a guessed loss of value: no sale, no net cost, and it says why; with one price and nothing to say it shows nothing (`worthShowing`).
- Owned's other way in is Chain (a new money chain: the Waypoints icon and one word) — in the bar from a tablet, beside Things | Stats on a phone; something you had is the + popup's "I had it" switch (critic, 24.11.2026); the ⋯ menu repeats neither — a way in shows once.
- The insurance list's "new price now" is a clean watch price only (a new offer or the shop's own page); its CSV never holds a formula (`csvCell`, OWASP's advice: every text cell quoted, a text starting with = + - @ — after spaces or full-width too — or a tab, return or line break gets an apostrophe, tested before the breaks are tidied) and its print view shows only the list.
- Stats follows the picked period (owner, 09.11.2026): a year is seen from 31.12 (today for this year), each card names it, and the definitions live in pure `statsModel.ts` (`periodOf`, `ownedAt`, `costOfUseIn`). "Could sell for" has no history: a past year knows it only for things still yours today — say so, never fill it in.
- A profit (made money, a chain ahead) is green — the success tone — on every screen (owner, 09.11.2026; before, only for things bought to sell). A chain's running result has the header's sign: + ahead, − a net cost. In the chain popup money paid is red (danger), money back green (success), the running result green when ahead and red when behind — `data-tone` + `tone-text`, never hex (owner, 23.11.2026: he removed "a loss on a thing you use is neutral, never red").
- The chain popup's last line (`chainModel.keptCost`, `keptWords`): which things you keep and what they cost you in total — their own price plus what the earlier sales passed on (a gain lowers it); a missing price or a pending rate says "not counted" and why, never a number (owner, 23.11.2026).
- Money chains: the Shop header's ⋯ lists every chain (`shop-chains`, `ChainsSheet`, Stats' `ChainRow`); each thing's line in the chain popup has a link icon that opens its record with the Money section open (`shop-item` `section: 'money'`) — links are changed only there (owner, 23.11.2026).
- Owned has no summary line (owner, 23.11.2026: a pointless extra line; `shownSummary`, `statsScopeOf` and `OwnedSummaryLine` are gone). Mine · Gone · All is a tab, never counted as a filter. Stats' "You own" keeps the whole collection (`ownedSummary`).
- Owned's filter bar is ONE line wherever it fits: it measures its own width (`useElementWidthRem`, pure `ownedRow.filterRowMode`) and folds the category, money chain and To sell behind Filters when they don't (folded, they share one wrapping row — the toggle never takes a line alone) — two rows on a phone sideways, three on a phone; every control is 36px, 44 on touch (`.input-bar`, `SegmentedControl size="sm"`, `Button`/`IconButton size="sm"`). The things use the page's whole width (their board has no 56rem main cap, `WIDE`) in column stacks of 21–40rem (owner, 23.11.2026).
- Needs a look's sheet is a chunk of its own (`NeedsALookSheet`, `lazyPart`): only the header's button and its count (tone of the most urgent row) are in the Shop page's first download — keep the page at ≤ 395 kB gzip (`verify-bundle-budget`, owner's AI work adds to it); the draft maths (`chainDraft`) loads on saving a chain, `newOffers.ts` / `oslo.ts` are the small modules the price API and the price words read.
- A missing rate reads "NOK rate missing" on every screen — never "rate pending"; the rate's editor offers **Fetch again** (`useFetchRatesAgain`) and says only what the answer says, never a cause it was not told (owner, 23.11.2026).
- A thing that left wears how as a banner on a big picture (the card, the record) and an icon badge on a row's or line's small picture (`DisposalRibbon`, `DisposalBadge`) — no word tag, no pill (owner, 23.11.2026). Sold is green, every other way neutral (`ownModel.disposalTone`; owner, 27.11.2026: "Sold mark is gray and almost unvisible. Make it green, shady green.").
